The Void [technical]

How the Void is built

The Void is the dimension strawberrymc:void_dim. Its terrain is a stack of named density functions combined in void/final.json, and it lives in a built-in datapack at src/main/resources/void_terrain. Three classes of file work together:

  • VoidTerrainPack.java registers the datapack.
  • tools/void_terrain/gen.py writes every JSON file inside the datapack.
  • data/strawberrymc/dimension_type/void_dim.json and the three biome JSON files sit in the mod's own data and are read alongside the pack.

VoidTerrainPack

VoidTerrainPack.init is called from StrawberrymcMod and listens for AddPackFindersEvent. The pack is a built-in server data pack, always enabled, and positioned at the top of the pack list, so its dimension/void_dim.json replaces the one MCreator generates from the VoidDim element. MCreator can regenerate its copy without affecting the terrain. The pack's pack.mcmeta declares format 101.1 for both min_format and max_format.

private static void addPack(AddPackFindersEvent event) {
	event.addPackFinders(Identifier.fromNamespaceAndPath("strawberrymc", "void_terrain"), PackType.SERVER_DATA, Component.literal("Strawberry MC Void terrain"),
			PackSource.BUILT_IN, true, Pack.Position.TOP);
}

The gen.py pipeline

gen.py is run from the java folder with python3 tools/void_terrain/gen.py. It defines small helpers that build density function JSON (noise, add, mul, mn, mx, ab, grad, sq, clamp, df), then runs in this order:

  1. Writes pack.mcmeta.
  2. Writes the 18 noise definitions to worldgen/noise.
  3. Builds the named density functions in a dictionary and writes each to worldgen/density_function/void/, so each piece can be tuned on its own.
  4. Loads MCreator's dimension/void_dim.json for its base settings, so changes to the VoidDim element carry over, then overrides the noise router, sea level, aquifers, ore veins, noise size and surface rule. The result is written to worldgen/noise_settings/void_dim.json.
  5. Replaces the dimension's biome source and settings reference and writes dimension/void_dim.json into the pack.
  6. Creates abyssal_plains.json and echoing_deep.json as copies of voidstone_peaks.json if those files do not exist, leaving existing biome files alone.

Sea level sits at the bottom of the world, so Void Tears appear only as pools. The surface rule places Voidstone at floor depth for all three biomes and adds no bedrock floor, leaving the world open below the terrain.

Density functions, layer by layer

A block is solid where the final density is positive. final is an interpolated maximum of four solid bodies, so each body adds rock wherever it is positive:

fns['final'] = {"type": "minecraft:interpolated", "argument":
   mx(mx(df('fractured_plain'), df('islands')), mx(df('pillars'), df('bridges')))}

fractured_plain

The plain combines five functions. The ground is raised by the mountains, then the whole slab is cut from beneath by the underside and across by the cracks:

fns['fractured_plain'] = mn(mn(mx(df('ground'), mn(df('mountains'), mn(df('canyons'), df('tunnels')))), df('underside')), df('cracks'))

ground

y_clamped_gradient from y=34 (value 1) to y=94 (value -1), plus 0.35 * void_ground with y_scale 0, plus 0.08 * void_roughness. The gradient crosses zero at y=64 and falls 1 density unit every 30 blocks, so one unit of void_ground moves the surface by 10.5 blocks. The source describes the plane as roughly y=50 to y=80.

underside

Gradient from y=-25 (value -1) to y=15 (value 1), plus 0.4 * void_underside. It crosses zero at y=-5 and changes 1 unit every 20 blocks, so one unit of noise moves the ragged underside by 8 blocks. Taking the minimum with this function removes everything below it, so cracks open into empty space.

cracks

fns['cracks'] = mul(12, add(ab(noise('void_cracks', 1, 0)), mul(-1, add(0.11, mul(0.06, noise('void_crack_width', 1, 0))))))

This is negative near the zero line of void_cracks, where |void_cracks| < 0.11 + 0.06 * void_crack_width. The width noise makes some cracks wide and some narrow. Multiplying by 12 gives the crack walls a steep edge.

islands

Three independent layers are combined with max. Each layer uses a triangular vertical profile that reaches 0 at its top height and -1.2 at its limits, added to island noise:

island_layer = lambda n, bottom, top, ceiling: add(mn(grad(bottom, -1.2, top, 0), grad(top, 0, ceiling, -1.2)), add(add(mul(1.4, noise(n, 1, 0)), -0.55), mul(0.1, noise('void_roughness'))))
fns['islands'] = mx(mx(island_layer('void_islands', 130, 166, 180), island_layer('void_islands_mid', 88, 112, 122)), island_layer('void_islands_low', -60, -30, -20))

The noise has y_scale 0, so an island's outline is the same at every height. Where the noise is strong the island keeps a wide flat top, and where it is weak only the narrow part of the profile stays positive, tapering the island into a cone. Ignoring roughness, an island exists at its top height where 1.4 * noise > 0.55.

pillars

fns['pillars'] = add(add(add(mul(4, noise('void_pillars', 1, 0)), -3.4), add(add(grad(40, 1, 60, 0), grad(160, 0, 175, -1)), grad(-20, -3, 10, 0))),
   mul(df('peaks_mask'), add(1.4, mul(0.6, noise('void_crags', 1, 1)))))

Between y=60 and y=160 the gradients are all 0, so a pillar stands where void_pillars > 0.85. The gradient at y=40 to y=60 (1 to 0) widens the foot, the gradient at y=160 to y=175 (0 to -1) closes the top inside the main island layer, and the gradient at y=-20 to y=10 (-3 to 0) stops pillars from hanging below the plain. The peaks_mask term is described on the Voidstone Peaks page.

bridges

fns['bridges'] = add(add(0.1, mul(-1, mx(ab(noise('void_bridges_a', 1, 0.5)), ab(noise('void_bridges_b', 1, 0.5))))), mul(0.2, mx(mx(mn(grad(140, -1, 155, 0), grad(172, 0, 185, -1)), mn(grad(95, -1, 104, 0), grad(116, 0, 125, -1))), mn(grad(-55, -1, -45, 0), grad(-34, 0, -24, -1)))))

Bridges are thin winding tubes where both 3D noises are near zero at once. The band term is 0 inside an island layer and -1 outside it, and the tube needs 0.1 + 0.2 * band to be positive, so bridges form only where the band is above -0.5.
