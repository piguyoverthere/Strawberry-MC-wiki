ComScript: Terminal commands

As you may already know, the Scripter block for ComScript has a native terminal that reports any building errors or can be used for running native alocate commands. Everything in terminal commands is case sensitive.

Command formatting

Most commands in Alo are specified using a data-driven JSON-like (referred to as pseudoJSON in this page) sequence after the command, such as:

alo stash {workspace:"my-workspace", file:"example-file.comscript", name:"my-stash", force:"true"}

Some data may be mandatory to perform the action, or may have a set of defined inputs. For example, in the code above, the "force" element can only have either "true" or "false" as data.

pseudoJSON can only be applied to a task, which are keywords including comments that cause a task in the java compiler that interprets the script.

Sub keywords

:clear

<keyword>:clear clears the terminal of previous text, including system logs, errors, warnings, or user command outputs/inputs. This command can only be used when no background processes are running, which can be paused or terminated with alo abort --force.

:pop

<keyword>:pop applies the saved item to your workspace. For example, alo stash:pop stash1 --force discards all uncommitted changes and applies all changes in "stash1" to your workspace. 

Keywords

alo

All Alo commands regarding the system itself including the terminal start with the "alo" keyword.

alo terminal:<mandatory action>

alo terminal performs actions in the terminal with a mandatory sub keyword required. 

Valid sub keywords (actions):

:clear

:push

:sort

alo stash {workspace:"opt workspace name", file:"opt file to selectively stash", name:"stash name (required)"}

alo stash temporarily stores all text within the specified file or if not specified, the terminal into a .md file stored in the level folder. Stashed changes are deleted after a session terminates, and need to be instanced by first popping/applying all changes with stash:pop, which restores all changes. A endemic attribute is alo stash --all (or just use the pseudoJSON data 'all:"true"'), which stashes all changes in git syntax in a .md file, and can only be popped when you have no uncommitted changes. Discard to commit all changes before popping a change stash. Changes are automatically discarded if alo stash is run forcefully

alo discard {workspace:"opt workspace name", file:"opt file to selectively discard from, if no file specified, discards all"}

alo discard discards all uncommitted changes in your workspace permanently.

alo build {workspace:"opt workspace name" output:"terminal"}

alo build emulates the Comscript scripts in your window and checks for any errors, warnings, or console.log texts. If your build output is too long, then the build logs are moved into the clog folder within your world. These can be accessed via alo fetch {file:"\clog"}.

alo fetch {file:"folder/file name, folders should start with \", index:#opt integer index specifies line to retreive from#}

alo fetch retrieves the contents of a file within the level folder of your world. The pseudoJSON input for index fetches the line of the file given, if the number given is greater than the number of newlines in the file, then it errors [index greater than file]. The input can also be a string by starting with char-#char# to get the specific character in the file. The following example outputs all contents in the clog file:

Command:

alo fetch {file:"\clog"}

Output:

[out.user
build-11-10-2026-8:29.23.log{
"contents":"
#Build Succesful#
#======Contents======#
"
stash-mystash.md{
"contents":"
*blockEvent.blockBreak{
say hello
}
"
}]

As you can see from the output above, the output is structured in pseudoJSON, with each file(s) receiving its own class.

Misc

echo(#contents#)

The echo() command is used to output text in the terminal which can be useful for reading system outputs that are stored in alo variables. The following example retrieves the version of alo you are using.

echo($("var1")) {"var1"($alo.getversion)}

Data structures, operators

Data structures

Data structures in Alo are either built-in and can be fetched without defining, or can be created.

Creation, modification, fetching

Data structures in Alo are created with comments that have applied pseudoJSON values, as pseudoJSON IDs can only be assigned to a task, which includes blank comments. Data structures do not need declaration, as they can be created in the same way you can modify a data structure in pseudoJSON.

The example below creates a variable named "myVar" and sets it to 3 by applying pseudoJSON into a blank comment string:

## {$myVar(3)} #note that if a variable named myVar was previously already declared, then this statement changes myVar to 3#

Different data structures can be created using the native data structure ID parentheses, which in the example above, would replace the normal brackets after $myVar.

Data typeParentheses type
Variable()
List{}
[UNRESOLVED: Extend list]

Fetching built-in data structures

Global data structures that are built-in can be fetched via a placeholder identifier, which in this case is "var1":

$myVersion = $("var1") {"var1"($alo.getversion)} #this example fetches a variable that outputs your current Alo version#

The "$" symbol in this case tells Alo the text within is a data structure ID, not an input.

Similarly, you can fetch arrays ([]), lists ({}) and dictionaries (<>) by replacing the parentheses after the equation:

Fetch global list:

## {$coolList{"item", "another-item", 3}
$coolList = ${"myList"}

Comments

Comments can be created in Alo with the hash symbol. All comments default to multiline, as the reader scans through the line until it reaches a terminator hash. The example below demonstrates comments:

#this is single-line comment#
#this is a multi
line comment#

Comments can also be embedded within parentheses and/or brackets of any depth but cannot be inside quotations, and continue until the comment is terminated with a hash.

echo("hello"#this comment will not be printed#)
echo("hello #this comment will be printed#")
