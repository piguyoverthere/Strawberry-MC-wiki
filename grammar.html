Grammar

The standard way to write wiki pages, so every page reads the same. These follow what most pages already do. When a page breaks one of these, fix it while you're editing.

Page titles

  • Name the page after the thing it describes, written the way it appears in the game: Ash, Burn Morels, Abandoned Belltower.
  • Capitalize every word of a name except short words in the middle (of, and, the, in): Brewing Effects and Potions.
  • When one page covers several variants, list them with commas: Badlands, Eroded Badlands, Wooded Badlands.
  • Technical pages add [technical] after the name, and pages of raw code add [raw]: Ash [technical].
  • The title is the page's only Heading 1. Don't use Heading 1 anywhere else on the page.

Headings

  • Use sentence case: capitalize only the first word and names. Write Item storage and World generation, not Item Storage or World Generation.
  • Names keep their capitals inside headings: Basalt Deltas, Village generation in the Badlands.
  • Go down one level at a time: Heading 2 for sections, Heading 3 inside them, then Heading 4. Don't skip from Heading 2 to Heading 4.
  • No full stop at the end of a heading.
  • Common section names are Overview, Properties, Crafting, Generation, Behavior and Technical details. Use these rather than a new word for the same thing.

Names of things in the game

  • Capitalize the names of blocks, items, mobs, biomes, structures, effects and enchantments, whether they're from Strawberry MC or vanilla Minecraft: 1 Ash, 1 Sulfur Slag, and 1 Charcoal; Gold, Copper and Iron Nuggets.
  • General words that aren't names stay lowercase: the player, a crafting grid, wind, loot.
  • Call the mod Strawberry MC, not "Strawberry Minecraft" or "the mod" on its own at the start of a page. Vanilla Minecraft is vanilla Minecraft, or just Minecraft.
  • Write gamerules, commands, tags and code names exactly as they are in the code, in a code box or as they appear: maxAshLayers, /give.

Tags in square brackets

Tags go straight after the word or sentence they describe, in lowercase, inside square brackets.

  • [coming soon]: planned but not in the mod yet.
  • [realism mode only]: only in Realism mode. Use this rather than "[realism exclusive]".
  • [Parabola Mode exclusive]: only in Parabola Mode.
  • [UNRESOLVED] is the one tag in capitals. It goes in bold at the top of a page or section that is incomplete or wrong, followed by what is missing: [UNRESOLVED] This page is incomplete. Use More → Mark as unresolved so the page also lands on the To Do list.

Writing style

  • Start the page with a sentence saying what the thing is: Tumbleweeds are non-natural entities that are blown in the direction of the wind.
  • Write in the present tense, about the game as it is: Ash builds up in Basalt Deltas, not Ash will build up.
  • Say the player, not you or I. Don't sign pages or add opinions; those go in Ideas or Threads & Debates.
  • Use now to mark a change from vanilla Minecraft: Gunpowder can now be crafted.
  • Use American spelling: color, behavior, armor, gray.
  • Use the serial (Oxford) comma in lists of three or more: emeralds, Gold, and Copper.
  • Put a space before an opening bracket and after a closing one: and (rarely) Deserts, not and(rarely)Deserts.
  • Keep sentences short. Use a bulleted list when describing several separate facts, steps or drops.

Numbers and units

  • Write game values as digits: 1 Ash, 25 health, 5 layers, 10 blocks.
  • Percentages use the % sign with no space: a 75% chance.
  • Write times in seconds or ticks (20 ticks are 1 second), and always plural except for exactly 1: 2.5 seconds.
  • Health and damage: say hearts for what the player sees and health points for code values, and don't mix them in one sentence.

Links and the end of the page

  • Link the first mention of another page's topic in each section. Names of elements link to their pages on their own.
  • End the page with a Heading 2 called Appendix: Related topics, listing links to related pages.
  • A technical page starts by linking back to its main page: Technical details for Ash.

Code

  • Put Java in a code box, with a Pseudocode tab explaining it in plain steps.
  • Keep the code's own indentation, using 4-wide tabs, and don't reformat it to fit.
