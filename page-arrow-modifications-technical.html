Arrow Modifications [technical]

Overview

This page covers the code behind Arrow Modifications. Modified arrows are ordinary minecraft:arrow items that carry three strings in their custom data: tip, shaft and fletching. There is no separate arrow item or entity. The strings travel through the system in this order:

  1. The Fletching Table opens FletchingTableGUIMenu through OpenFletchingTableGUIProcedure [raw].
  2. CalcFletchingProcedure [raw] reads the slots every player tick and writes the strings into the minecraft:custom_data component of the output stack.
  3. Taking the output runs ShrinkFletchingTableIngredientsProcedure [raw], which consumes the inputs.
  4. IronBowItem fires an arrow and calls ArrowImpactEffectsProcedure [raw], which copies the strings from the ammo item into the arrow entity's persistent data.
  5. ArrowFlightVisualsProcedure [raw] handles flight behavior and block impacts on every entity tick.
  6. TriggerEntityHitProcedure [raw] catches damage dealt by an arrow and runs ArrowEffectExecuterProcedure [raw].

Fletching Table menu

Opening the menu

OpenFletchingTableGUIProcedure subscribes to PlayerInteractEvent.RightClickBlock, ignores the off hand, and opens the menu for a ServerPlayer when the clicked block is Blocks.FLETCHING_TABLE. The menu type is strawberrymc:fletching_table_gui, registered in StrawberrymcModMenus and generated from the element FletchingTableGUI.mod.json. FletchingTableGUIScreen draws strawberrymc:textures/screens/fletching_table_gui.png at 176 by 166 pixels with the label gui.strawberrymc.fletching_table_gui.label_empty (==>) at 88, 39.

Slots

The menu holds a five-slot ItemStacksResourceHandler. It is not bound to a block entity, so the contents exist only while the menu is open.

Calculating the output

FletchingTableGUIMenu.onPlayerTick listens to PlayerTickEvent.Post and runs CalcFletchingProcedure for any player with this menu open. The output stack starts as a copy of slot 4, so custom data already on the input arrows carries over. All recipe logic sits inside one check that slot 4 is plain arrows with a count of at least 5.

If at least one string was set, each non-empty string is written with CustomData.update, and slot 3 is set to the result with a count of 5. If none was set, slot 3 is cleared. The three categories are independent, so one output can carry a tip, a shaft and a fletching together. When slot 4 does not meet the check, the procedure does nothing and the output slot keeps its contents.

if (!(var_tip).equals("")) {
	{
		final String _tagName = "tip";
		final String _tagValue = var_tip;
		CustomData.update(DataComponents.CUSTOM_DATA, output_arrow, tag -> tag.putString(_tagName, _tagValue));
	}
}

Taking the output and closing the menu

Slot 3's onTake calls slotChanged(3, 1, count). On the client this sends a FletchingTableGUISlotMessage (payload strawberrymc:fletching_table_gui_slots) and runs the same handler locally. handleSlotAction first returns if the chunk at the menu position is not loaded, a guard against arbitrary chunk generation, and then runs ShrinkFletchingTableIngredientsProcedure when the slot is 3 and the change type is 1.

_menu.getSlots().get(0).remove(5);
_menu.getSlots().get(1).remove(5);
_menu.getSlots().get(2).remove(5);
_menu.getSlots().get(4).remove(5);
_player.containerMenu.broadcastChanges();

Five items are removed from all four input slots, including any ingredient that did not contribute a string. The procedure is the only place ingredients are consumed.

In removed, every slot from 0 to 4 is returned to the player with placeItemBackInInventory, or dropped if the player is dead or disconnected. Slot 3 is part of that loop, so a stack sitting in the output when the menu closes also goes to the player.

Firing: Iron Bow

IronBowItem (strawberrymc:iron_bow, element IronBow.mod.json) is the only caller of ArrowImpactEffectsProcedure, so it is the only weapon that transfers the strings to the projectile. It is listed in the Combat creative tab and in the minecraft:enchantable/durability item tag.

releaseUsing runs in this order: it finds the ammo, creates and spawns an Arrow, plays entity.arrow.shoot, damages the bow by 1, shrinks the ammo stack by 1 in survival, and finally calls ArrowImpactEffectsProcedure.execute at the shooter's position.

Copying the data to the arrow entity

ArrowImpactEffectsProcedure picks the ammo stack to read: the off hand if it holds an arrow, otherwise the first arrow in entity item slots 0 to 35. It runs after the ammo was shrunk, so when the shot used the last arrow of a stack, the strings come from the next arrow stack found. It then writes the three strings to the persistent data of the closest Arrow in a 4-block-wide box centered on the shooter.

(findEntityInWorldRange(world, Arrow.class, x, y, z, 4)).getPersistentData().putString("tip", (ammo_item.getOrDefault(DataComponents.CUSTOM_DATA, CustomData.EMPTY).copyTag().getStringOr("tip", "")));
(findEntityInWorldRange(world, Arrow.class, x, y, z, 4)).getPersistentData().putString("shaft", (ammo_item.getOrDefault(DataComponents.CUSTOM_DATA, CustomData.EMPTY).copyTag().getStringOr("shaft", "")));
(findEntityInWorldRange(world, Arrow.class, x, y, z, 4)).getPersistentData().putString("fletching", (ammo_item.getOrDefault(DataComponents.CUSTOM_DATA, CustomData.EMPTY).copyTag().getStringOr("fletching", "")));

In flight

ArrowFlightVisualsProcedure subscribes to EntityTickEvent.Pre and acts on entities that are instances of Arrow. "Moving" below means at least one component of getDeltaMovement() is nonzero. Each tick runs these steps in order:

  1. Shooter stamp: if has_shooter_stamp is false and a player is inside a 4-block-wide box around the arrow, the closest player's display name is stored in shooter_name and the flag is set.
  2. Trail particles while moving.
  3. Block impact, described below.
  4. Phantom acceleration.
  5. Echo homing.
ModifierFlight effect
shaft = blaze1 SMALL_FLAME per tick, spread 0.05
shaft = breeze1 SMALL_GUST per tick, spread 0.1
fletching = phantom1 ASH per tick, spread 0.1. While moving and out of water, velocity is multiplied by 1.013 every tick
tip = echoHoming, described below

Echo homing

Each tick, the arrow finds the closest LivingEntity in a 12-block-wide box, which reaches 6 blocks each way. Only that one entity is considered. If its display name differs from shooter_name, the arrow is moving and the target is more than 4 blocks away, the arrow's velocity gains a steering term. A SCULK_SOUL particle is sent at the target.

velocity.x += (target.x - arrow.x) / (distance * 0.13)
velocity.y += (target.y - arrow.y) / (distance * 0.13) + 1
velocity.z += (target.z - arrow.z) / (distance * 0.13)

The steering vector has a length of 1 / 0.13, about 7.69 blocks per tick, toward the target. The y component also gains a flat 1 each tick.

Block impact

A separate branch in ArrowFlightVisualsProcedure runs once per arrow, the first tick its velocity is exactly zero, and sets ground_impact so it cannot run again. Fills are server commands run with owner permission at the arrow's position, with output suppressed.

shaft = blazeAny tip except goldfill ~-1 ~-2 ~-1 ~1 ~2 ~1 minecraft:fire replace minecraft:air
shaft = blazetip = goldfill ~-3 ~-3 ~-3 ~3 ~3 ~3 air replace water
shaft = blazeAlwaysEntities within 1 block on each axis burn for 10 seconds; 5 LAVA particles, spread 3; entity.generic.explode at volume 1 and pitch 1
tip = spongeShaft is not aquafill ~-2 ~-2 ~-2 ~2 ~2 ~2 air replace water
tip = gunpowderShaft is not aquaExplosion of power 1.5 with Level.ExplosionInteraction.MOB, and 1 EXPLOSION_EMITTER particle

CalcFletchingProcedure has no ingredient that sets the shaft to aqua, so the two aqua conditions always pass for crafted arrows.

Entity hit

TriggerEntityHitProcedure subscribes to LivingIncomingDamageEvent. When event.getSource().getDirectEntity() is an Arrow, it calls ArrowEffectExecuterProcedure with the damaged entity and the arrow. Coordinates are the damaged entity's position. Effects run in the order listed, and more than one can apply.

The breeze effect also runs particle minecraft:wind_burst ~ ~ ~ 0 0 0 0 1 and plays the explosion sound. The one-tick delay uses StrawberrymcMod.queueServerWork(1, ...).

	if (entity instanceof LivingEntity) {
		if ((immediatesourceentity.getPersistentData().getStringOr("tip", "")).equals("gold")) {
			entity.setDeltaMovement(new Vec3(0, 1.3, 0));
		} else {
			entity.setDeltaMovement(new Vec3(0, 1.2, 0));
		}
	}
});

Sponge branch

The hit procedure's water-removal branch checks shaft = sponge, while CalcFletchingProcedure stores sponge as a tip. A crafted sponge arrow therefore removes water only through the block impact branch.

Amethyst block tags

The non-living branch of the amethyst effect, which breaks a block and plays a glass or dripleaf sound, is only reachable for a non-living target. TriggerEntityHitProcedure is driven by a living damage event, so that branch does not run in play. It looks up the tag keys mod:amethyst_shard_pierceable and mod:vegetation. The tag files ship as data/strawberrymc/tags/block/amethyst_shard_pierceable.json and data/strawberrymc/tags/block/vegetation.json.

Advancement

strawberrymc:echo_shard_advancement, titled "Take (Auto) Aim", has minecraft:adventure/shoot_arrow as its parent and a single minecraft:impossible criterion, so it is granted only by command.
