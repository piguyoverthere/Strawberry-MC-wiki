Breakpoints, Call Stacks, and Debugging Methods

Other than using logs and chat messages for debugging, other tools are provided by the Scripter IDE to make ComScript less of a headache. This section details how to use these tools and basic knowledge needed for debugging

Breakpoints

Breakpoints are a concept that pauses a script during a debug run that allows the user to check the call stack (you will learn about later), data structure values during that moment, and other info as the script is temporarily paused during that time. Breakpoints in ComScript can be declared by inserting breakpoint(<breakpoint name>);, or using alo breakpoint (you will learn about Alo terminal commands later). Once a breakpoint is initiated in ComScript, the terminal outputs [<time signature>] \comscript > [!]: Breakpoint started [<breakpoint age>].

You might have noticed the breakpoint name input, which is a unique value that a different breakpoint cannot have (or else errors: Breakpoint error) that identifies the breakpoint, as multiple breakpoints can be in a single script. Make sure this value is something easy to remember and type, as in order to clear that breakpoint, you will need the identifier value.

After you are done debugging and want the script to continue, you can use alo breakpoint clear <breakpoint name> to remove the breakpoint, or alo breakpoint clear --all to void all breakpoints. If you the breakpoint you try to clear does not exist, it errors: Invalid breakpoint identifier used.

Fetch call stack

The call stack in ComScript in basic terms is a queue for tasks that ComScript needs to perform for that tick, which can be used for debugging and during breakpoints. The call stack when fetched with alo fetch-callstack lists all of the tasks from most priority to least priority that need to be executed.

Example:

alo fetch-callstack
#THIS IS JUST AN EXAMPLE AND MAY NOT ACCURATELY OUTPUT CORRECT API NAMES#
#[example] expected output:#
[11-18-2026-3.21.04] \comscript > [!] #RETURN call stack#
[11-18-2026-3.21.04] \comscript > [!] task: get_entity_rel_key
