Prismatic Sensor [technical]

Overview

Prismatic Sensors stop survival players from changing an Ocean Monument. Four stand in each monument, one per quadrant. The protection lives in monument/PrismaticSensors.java, which reads the position of the block being changed and checks the block state of that quadrant's sensor. The sensor has no block entity and no ticking of its own. The glyphs around it are generated by the client in monument/client/SensorParticles.java.

Where they are

MonumentShell.buildSensors runs after the shell, gazebo and arena. Positions come from Layout.sensors(), at local coordinates with the entrance at z=0.

Each sensor is at box.minY() + 5, on the 2-block floor plus a 3-block pedestal. The pedestal is 3x3x3 minecraft:dark_prismarine, with minecraft:sea_lantern in the four corners of its top layer.

Protection

Protected area

A sensor has no radius. Layout.sensorFor(pos) splits the monument into four quadrants around (minX + 58, minZ + 58) and returns the sensor in the same quadrant as pos. Layout.contains limits the area to the building's X and Z range, from minY - 1 to maxY. The protected volume is therefore the entire 116x116 building, including the hall, roof, gazebo and arena.

public static @Nullable BlockPos guardingSensor(ServerLevel level, BlockPos pos) {
	MonumentShell.Layout layout = monumentAt(level, pos);
	if (layout == null)
		return null;
	BlockPos sensor = layout.sensorFor(pos);
	return level.isLoaded(sensor) && level.getBlockState(sensor).is(StrawberrymcModBlocks.PRISMATIC_SENSOR.get()) ? sensor : null;
}
guardingSensor(level, position):
    find the monument at this position; if none, return nothing
    find the sensor position that guards this position
    if that spot is loaded and holds a prismatic sensor:
        return it
    else:
        return nothing

The block at the sensor's position is the only state. A quadrant is protected only when that block is loaded and is the active sensor. Swapping it for the deactivated block lifts the protection for that quadrant.

Events

PrismaticSensors.init registers onBreak for BreakBlockEvent and onPlace for BlockEvent.EntityPlaceEvent. Both run only on a ServerLevel. onPlace runs only when the placing entity is a Player.

private static boolean isExempt(@Nullable Player player, BlockState state) {
	return player == null || player.isCreative() || player.isSpectator() || state.is(StrawberrymcModBlocks.ANCIENT_PRISMARINE.get());
}

private static void onBreak(BreakBlockEvent event) {
	if (!(event.getLevel() instanceof ServerLevel level))
		return;
	BlockPos pos = event.getPos();
	if (!isExempt(event.getPlayer(), event.getState())) {
		BlockPos sensor = guardingSensor(level, pos);
		if (sensor != null) {
			event.setCanceled(true);
			refuse(level, sensor, pos);
		}
		return;
	}
a block break is exempt if there is no player, the player is in creative or spectator mode, or the block is ancient prismarine
when a block is broken:
    only run on the server
    if the break is not exempt:
        find a sensor guarding this position (guardingSensor)
        if there is one:
            cancel the break
            run refuse for that sensor and position
        stop

The order is: exemption check, then sensor lookup, then cancel. Ancient Prismarine is exempt whether it is being broken or placed. After an exempt break of Ancient Prismarine, onBreak goes on to the vent check described on Ocean Monument.

Refusal feedback

Cancelling the event leaves the block where it was, with no drop. refuse then plays its feedback at the refused block, on the server, so every nearby player sees it.

Switching sensors

PrismaticSensors.registerCommands adds /sensors, which requires Commands.LEVEL_GAMEMASTERS. The command resolves the monument at the command source's position and replaces each loaded sensor position with Block.UPDATE_ALL.

SyntaxEffectSuccess message
/sensors activatePlaces prismatic_sensor at all loaded sensor positions of the monument."Activated N Prismatic Sensor(s)"
/sensors deactivatePlaces deactivated_prismatic_sensor at all loaded sensor positions of the monument."Deactivated N Prismatic Sensor(s)"

Outside a monument it fails with "Stand inside an ocean monument to switch its sensors".

Glyph particles

Finding sensors

Random block ticks would reach a single sensor only every few seconds, so SensorParticles finds them directly on ClientTickEvent.Post. Every 20 ticks (1 second) scan rebuilds a list of positions. It covers 3 chunks around the player (7x7 chunks) and 3 sections above and below the player's section. Sections that are all air, or whose palette cannot contain the block, are skipped before any per-block loop.

LevelChunkSection section = chunk.getSection(index);
if (section.hasOnlyAir() || !section.getStates().maybeHas(state -> state.is(sensor)))
	continue;
get this chunk section
if it is all air or cannot contain a sensor block:
    skip to the next section

On every tick, each listed position that is still an active sensor spawns (int) 0.6F + (random < 0.6 ? 1 : 0) glyphs, which averages 0.6 per tick, or 12 per second, per sensor. Deactivated sensors fail the block check and spawn none. The game does not spawn glyphs while paused.

Spawning

The particle type is strawberrymc:sensor_glyph, registered in PrismaticSensors.PARTICLES. Its definition is sensor_glyph.json in the built-in monument_cutscene resource pack and lists the 26 enchanting glyph sprites minecraft:sga_a to minecraft:sga_z.

spawn picks a random horizontal side and one of the two panels, centerd at 4.5/16 or 11.5/16 across the side with a half-width of 1.2/16. Height is random between 2.5/16 and 13.5/16. The glyph starts 0.52 out from the block's center. The particle's velocity arguments carry data, not velocity: the side's outward normal in X and Z, and the distance along the side to the gap between the panels in Y.

double nx = side.getStepX(), nz = side.getStepZ();
// Tangent along the side; the glyph's gap target is (0.5 - across) along it
double tx = -nz, tz = nx;
double x = pos.getX() + 0.5 + nx * 0.52 + tx * (across - 0.5);
double z = pos.getZ() + 0.5 + nz * 0.52 + tz * (across - 0.5);
level.addParticle(PrismaticSensors.SENSOR_GLYPH.get(), x, pos.getY() + up, z, nx, 0.5 - across, nz);

get the direction running along that side
x, z = the block's center, pushed 0.52 out through the side, then shifted along the side by (across - 0.5)
spawn a SENSOR_GLYPH particle there at height up, moving outward with sideways target 0.5 - across

Motion

SensorParticles.Glyph extends SingleQuadParticle, has no physics or gravity, and draws in the translucent layer at block light 15. Lifetime is 60 to 84 ticks (3 to 4.2 seconds). Size is 0.06 to 0.11. Color is (0.55, 0.9, 1.0) multiplied by a brightness of 0.85 to 1.0. Position is computed from the particle's age fraction t, not integrated from velocity.

PhaseAge fractionMotion
Out0 to 0.25Moves from the panel to its hover point with a cubic ease out. The hover point is 0.45 to 1.0 blocks out, with random drift along the side (up to 0.175) and vertically (up to 0.15).
Hover0.25 to 0.62Stays at the hover point, bobbing by sin(age * 0.25) * 0.03.
Suck in0.62 to 1Moves to the gap between the panels, at the glyph's starting height, with p = ((t - 0.62) / 0.38)^2: slow at first, then fast.

Alpha is min(1, min(t / 0.1, (1 - t) / 0.08)). The glyph shrinks to nothing over the final 10% of its life.
