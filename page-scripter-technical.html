Scripter [technical]

The block

ScripterBlock extends BaseEntityBlock and implements GameMasterBlock. It renders with RenderShape.MODEL. getTicker returns ScripterBlockEntity::serverTick on the server and null on the client.

Redstone edge handling

@Override
protected void neighborChanged(BlockState state, Level level, BlockPos pos, Block block, @Nullable Orientation orientation, boolean movedByPiston) {
	if (level.isClientSide() || !(level.getBlockEntity(pos) instanceof ScripterBlockEntity scripter))
		return;
	boolean powered = level.hasNeighborSignal(pos);
	if (powered != scripter.isPowered()) {
		scripter.setPowered(powered);
		// Runs once on each rising edge, a tick later like a command block
		if (powered)
			level.scheduleTick(pos, this, 1);
	}
}

The last known power state is kept in the block entity and saved as Powered, so reloading a powered Scripter does not count as a new edge. A change from unpowered to powered schedules a block tick 1 tick later, and tick calls scripter.run(). A falling edge only updates the stored state. Power is examined only in neighborChanged, so a Scripter placed where it is already powered runs on its first neighbor update that sees the signal.

Opening the editor

useWithoutItem returns PASS if the block entity is missing or player.canUseGameMasterBlocks() is false. Otherwise it returns SUCCESS and, on the client only, calls ScripterScreen.open(scripter).

The instance holds the script, the log, the list of Listener records, the stored power state, clientListening, needsSync and currentLine. A static weak set, LISTENING, holds the Scripters that have registered listeners, so event dispatch does not search the world and does not keep removed block entities alive.

Listeners, their source and the runner's variables are held only in memory, so a loaded Scripter has no active timers or event blocks until the script is run again. sync clears needsSync, calls setChanged and, on the server, calls level.sendBlockUpdated with flag 3. getUpdateTag uses saveCustomOnly and getUpdatePacket uses ClientboundBlockEntityDataPacket.create, so the same saved values are what the client receives.

setScript cuts any text over the limit down to 32000 characters and marks the block entity changed.

Editor packet

The editor's only packet is ComScript.EditScripter, with id strawberrymc:edit_scripter, registered with registrar version "1" as play-to-server. Its stream codec is a BlockPos, a UTF-8 string of at most 32000, and a VAR_INT action.

OrdinalActionServer response
0SAVEStores the script and calls sync().
1RUNStores the script and calls run().
2STOPStores the script and calls stop(true).
3CLEAR_TERMINALCalls clearLog() and leaves the script alone.

	return;
Action action = Action.values()[Math.floorMod(payload.action(), Action.values().length)];
if (action != Action.CLEAR_TERMINAL)
	scripter.setScript(payload.script());
switch (action) {
	case SAVE -> scripter.sync();
	case RUN -> scripter.run();
	case STOP -> scripter.stop(true);
	case CLEAR_TERMINAL -> scripter.clearLog();
}

Run and stop lifecycle

run() is reached from the redstone tick or the Run packet, and only does anything on a ServerLevel.

  1. stop(false) silently clears the previous listeners and removes the Scripter from LISTENING.
  2. The script is parsed. A SyntaxError logs Syntax error: <message> at its line, syncs and returns, leaving the Scripter with no listeners.
  3. Running script is logged.
  4. A new ComScriptRunner runs the statements with a new source.
  5. If listeners were registered, Listening for <list> is logged, naming each distinct listener: an event name, every tick or every N ticks.
  6. currentLine returns to -1 and the block entity syncs.

stop(announce) clears listeners. With announce true and listeners present, it also logs Stopped and syncs. setRemoved clears the listeners and leaves the set as well, which covers breaking or unloading the Scripter.

serverTick runs each timer that is due, resets currentLine, and then sends pending terminal output:

public static void serverTick(Level level, BlockPos pos, BlockState state, ScripterBlockEntity scripter) {
	for (Listener listener : List.copyOf(scripter.listeners))
		if (listener.isTimer() && (level.getGameTime() - listener.started()) % listener.interval() == 0)
			listener.runner().run(listener.body(), listener.source());
	scripter.currentLine = -1;
	// Every-tick output is sent to the client a few times a second, not every tick
	if (scripter.needsSync && level.getGameTime() % 5 == 0)
		scripter.sync();
}

The editor screen

ScripterScreen is a custom text editor drawn directly, not a vanilla text box. It does not pause the game (isPauseScreen is false), reports as in-game UI, and closes itself in tick if the block entity is removed. Script text, line numbers and the terminal use the strawberrymc:jetbrains_mono font.

The text model is one String, a cursor, an anchor for the selection, and a lineStarts list found by binary search in lineOf. textChanged rebuilds lineStarts and the color array after every edit. Tabs in a loaded script become 4 spaces.

Typed text passes through charTyped, which accepts characters allowed in chat. Inserted text has \r\n and \r normalized to \n and tabs expanded to 4 spaces. An insertion that would take the script over 32000 characters is refused.

Undo

Undo and redo are stacks of Snapshot(text, cursor), with undo capped at 200 entries. Typing in a burst counts as one step:

private void remember(boolean typing) {
	long now = System.currentTimeMillis();
	if (!typing || now - lastEdit > 1000 || undo.isEmpty())
		undo.push(new Snapshot(text, cursor));
	lastEdit = typing ? now : 0;
	while (undo.size() > 200)
		undo.removeLast();
	redo.clear();
}

Mouse

  • Left click in the editor places the caret. Shift-click extends the selection, and dragging selects.
  • Double-click selects the word under the pointer. Word characters are letters, digits, _ and $.
  • The wheel over the editor scrolls 3 lines. Horizontal scrolling moves 3 character widths per step.
  • The wheel over the terminal scrolls 1 log line, limited to the log's length.

Scan order

The method is one pass that keeps a statementStart flag. At each position it tests:

  1. Comments, with the same two forms as the interpreter.
  2. Double-quoted strings, which end at a closing quote or at the end of the line.
  3. The boolean literals <true;> and <false;>.
  4. ;, newline, ( or {, which set statementStart.
  5. Other whitespace, which changes nothing.
  6. * at a statement start, with following letters, digits and dots.
  7. $ variables.
  8. @ selectors, whose [ ] group ends at a newline at the latest.
  9. & tokens within 12 characters of a ; and matching &[#A-Za-z0-9\\]+.
  10. Numbers, ~ and ^, and - or . directly before a digit when not following a letter or digit.
  11. Words, which may contain _, ., and : before a letter, plus a trailing : for local: and global: and a trailing ^ before (.

A word's color is chosen in priority order:

if (call && ComScriptSyntax.isFunction(word) || io.github.strawberrymc.comscript.ComScriptFetchers.BARE.contains(word.toLowerCase()))
	color = FUNCTION;
else if (ComScriptSyntax.KEYWORDS.contains(word) || word.equals("mod"))
	color = KEYWORD;
else if (ComScriptSyntax.SUBCOMMANDS.contains(word))
	color = SUBCOMMAND;
else if (statementStart && (commands.contains(word) || word.equals("store")))
	color = COMMAND;
