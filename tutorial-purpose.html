Purpose/Basics

The developer team at Strawberry MC made ComScript and the Scripter to improve vanilla scripting beyond commands and make simple solutions for problems such as using scoreboards as a compromise to variables. Furthermore, ComScript replaces the need for extensive chain command blocks, condensing it into a single block. ComScript also makes commands consistent in input formatting, since the input formatting for commands (especially bedrock edition) have varied and inconsistent inputs. ComScript instead uses ComScript Object Notation (different from alo based psuedoJSON) to define the inputs, such as:

// Assume vanilla wrapper here
say hello {
    .textColor(rgb(1, 1, 1)); //each of these are components
    .fontFamily{
        "sans-serif";
        "helvetica"
    };
}
// Note these components can be in any order within the curly brackets

Typical command syntax can still be used so seasoned players can still use their muscle memory and to prevent breaking anyone's command projects. See Syntax:Vanilla command integration for details.

Though ComScript may be more efficient to use, ComScript is much slower to execute, as complex java based interpreters have to read the script character by character, which may also cause lag spikes.

In the next section, you will learn about the syntax of ComScript.

Permission levels

Permission levels in ComScript range from a integer 1-4, with the following definitions:

  • Level 1: Guests have no access to server-side commands and are affected by custom protected tickingareas.
  • Level 2: Managers can run standard cheat commands but not run multiplayer management commands (such as /deop, /op, /kick, /debug, etc.) or administrative commands that can alter the server itself.
  • Level 3: Moderators have access to multiplayer management commands (such as /deop, /op, /kick, /debug, etc.) but not administrative commands that can alter the server itself.
  • Level 4: Operators have access to all commands including administrative commands to stop or start the server.

Space formatting

ComScript is spacing sensitive

void  function()   { // This is illegal, as there are too many spaces between each word.

Each word/character should have only 1 space between, such as how a space is needed between the condition and curly bracket:

if <true;> == <true;> { // Notice the space between <true;> and {.
}

Terminology

Relative location selectors

Relative location selectors include any selectors that are location or distance based, meaning that they must have a starting point of execution. These include:

  • @p
  • @n

If no execution marker is included, they start from the Scripter's location. Selectors are resolved by Minecraft in its own order, so @p and @n find the nearest match first.

Token

A token is any symbol, symbolized, or packaged string that can be used in a value type.

Quotations

Quotations in comscript are unidirectional, meaning that they do not directionally encapsulate text. The straight double quote and both curly double quotes all open and close a string, and can be mixed. Strings can also use single quotes.

Execution location auto-assumption key

Commands executing without a specified location (specified via the mark keyword) are executed based off of the following rules:

If the script line is inside an event block, it is executed at the event's position. If it is inside a timer, it starts from the location the timer was started at.

If no specified location is fetched from the previous condition(s), the execution marker (if one was fetched correctly) becomes the execution location. If no location is fetched, valid selectors execute from the Scripter's location:

  • @p (for locational relative/proportional selectors such as closest player/entity, this is relative to the location of execution) [property P1]
  • @e [see property P1]
  • @n [see property P1]

@s is the entity running the statement. A script starts with no entity, so @s matches nothing until execute as or an event block supplies one.

Using tokens

Every token in the substitution key works in strings and commands, and so does any decimal code like &#36;. They are replaced after $variables are filled in, so &dollar; puts a real $ in a command. The semicolon that closes a token never ends the statement.

Outside quotes, an & joined to a short word counts as a token when a semicolon follows it, so that semicolon doesn't end the statement. To print an & joined to a word, use its token: say Tom&amp;Jerry;.
