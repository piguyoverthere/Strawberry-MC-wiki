ComScript

ComScript is a coding language based on Minecraft Commands that eliminates the need for long chains of Command Blocks. ComScript is executed by typing scripts into the Scripter block.

ComScript is the scripting language of Strawberry MC: it mixes ordinary Minecraft commands with variables, math, conditions and values read straight from the world. A script can run once, repeat on a tick timer, or react when blocks are broken or placed, players join, or entities die. Mistakes are reported with their line number instead of stopping the server. See ComScript [technical].

Errors

Errors due to syntax or any other reason when the script is run are shown in the terminal located at the bottom of the UI. All errors are red text, warnings as yellow text, and logs as white text.

A statement that fails while the script is running is reported and the script carries on with the next statement.

Syntax error

This error appears when a script can't be read, for example when a statement has no semicolon. Nothing in the script runs, and the terminal shows the first problem with its line number.

Error example:

say hello
say goodbye;

The first line gives Syntax error: Missing ; at the end of the line.

Error: Undefined data structure(s)

This error appears when undefined variables are used.

Error example:

say $missing;

Error: No mandatory execution marker found

This error appears when a mark add line can't find a position, usually because the selector in mark add relative matches nothing. The marker stays where it was, and the script continues.

Error example:

mark add relative @e[tag=no_such_tag] ~ ~ ~;

Error: Unexpected data type in input

This error occurs when an incompatible data type is used in an input.

Error example:

store new a = "x" - 1;

The - operator is for integers and floats only.

Technical details

Terminology

Relative location selectors

Relative location selectors include any selectors that are location or distance based, meaning that they must have a starting point of execution. These include:

  • @p
  • @n

If no execution marker is included, they start from the Scripter's location. Selectors are resolved by Minecraft in its own order, so @p and @n find the nearest match first.

Token

A token is any symbol, symbolized, or packaged string that can be used in a value type.

Quotations

Quotations in comscript are unidirectional, meaning that they do not directionally encapsulate text. The straight double quote and both curly double quotes all open and close a string, and can be mixed. Strings can also use single quotes.

Execution location auto-assumption key

Commands executing without a specified location (specified via the mark keyword) are executed based off of the following rules:

If the script line is inside an event block, it is executed at the event's position. If it is inside a timer, it starts from the location the timer was started at.

If no specified location is fetched from the previous condition(s), the execution marker (if one was fetched correctly) becomes the execution location. If no location is fetched, valid selectors execute from the Scripter's location:

  • @p (for locational relative/proportional selectors such as closest player/entity, this is relative to the location of execution) [property P1]
  • @e [see property P1]
  • @n [see property P1]

@s is the entity running the statement. A script starts with no entity, so @s matches nothing until execute as or an event block supplies one.

Using tokens

Every token in the substitution key works in strings and commands, and so does any decimal code like &#36;. They are replaced after $variables are filled in, so &dollar; puts a real $ in a command. The semicolon that closes a token never ends the statement.

Outside quotes, an & joined to a short word counts as a token when a semicolon follows it, so that semicolon doesn't end the statement. To print an & joined to a word, use its token: say Tom&amp;Jerry;.

Scripter block

The Scripter is the block that runs ComScript in game. It is an operator-only block like the command block: it can't be broken in survival and drops nothing. Right-clicking it opens a black code editor (JetBrains Mono font, color-coded keywords) with the terminal underneath.

  • A redstone pulse runs the script once, one tick after the signal turns on.
  • The Run button saves and runs the script, Stop saves it and stops its timers and event blocks, Done (or Esc) saves and closes the editor, Cancel closes the editor without saving, and Clear empties the terminal.
  • Running the script again stops the timers and event blocks the last run started.
  • One run (or one tick of a timer, or one event) can run at most 10000 statements, so a script can't freeze the server.
  • A script can be up to 32000 characters long, and the terminal keeps its last 200 lines.
  • Command output appears in the terminal: errors in red, warnings in yellow, everything else in white, each with the time, and with the line number when it came from a line of the script.

The Scripter is an operator-only block, similar to a command block, that holds and runs a whole ComScript script. Right-clicking it opens a code editor with color-coded text, line numbers and a terminal that shows errors in red, warnings in yellow and everything else in white. A redstone pulse or the Run button starts the script, and its timers and event listeners keep going until it is run again, stopped, or the block is removed. See Scripter [technical].

Definers in the Scripter

The Scripter accepts local: and global: in front of any statement. They don't change what the statement does, because every script is a single file.

Syntax

Log outputs

Log outputs can be used for debugging in ComScript to detect whether a code triggered and embed variables in that instance. The following example outputs a variable named "var2":

console.log("var2 is ", var2, ".")

Definers

Definers go directly in front of a statement. See Definers in the Scripter.

local:

Example:

local:mark add 0 64 0;

global:

Example:

global:say hello;

Execution marker/location

Execution markers mark where the script would start executing if you would like to override the location of where the scripter block is placed. Execution markers can be defined using the following:

mark add <x y z> <optional: static or mobile>;

Relative execution markers

Relative execution markers are placed depending on the base selector and the spacing. These allow scripts to execute depending on the selector; which means that you can have scripts executed at a specific tagged sheep for example.

Syntax:

mark add relative <base selector> <tilde defined relative location>;

Example:

mark add relative @e[type=sheep,tag=cheese] ~ ~10 ~;

Setting the marker

  • mark add <x y z>; takes absolute or ~ coordinates. The mobility word (static or mobile) is optional and doesn't change anything for a fixed position.
  • mark add relative <selector> <~ ~ ~>; finds the entity once, at that line. If the offset is left out, it marks the entity's own position.
  • A marker moves every statement after it in the same block. Statements inside run { } and event blocks start from the position the block was given.
  • If the selector matches nothing, the line gives Error: No mandatory execution marker found and the marker stays where it was.
  • store.global set excrd = <x y z>; does the same as mark add <x y z>;.

Input formatting

Inputs in comscript can accept the following formats

  • String — expected formatting: "<value>"
  • Binary (useful for raw files) — expected formatting: bin(<value>)
  • Boolean — expected formatting: <true;> or <false;>
  • Float — expected formatting: <value>
  • Integer — expected formatting: <value>
  • Selector — expected formatting: @e[type=pig]
  • Text style — expected formatting: see Text styles

If you want to change/define the format of a variable or value, you can use the following anywhere a value goes, for example store new text = str(5);:

Convert to string

string(<value>)
str(<value>)

Convert to boolean

Only 1-digit binary integers, and strings with boolean names can be converted.

boolean(<value>)
bool(<value>)
booleanState(<int0-1>)

Convert to binary

Anything can be converted into binary, as it is the raw data type.

bin(<value>)
createBin(<value>)

Example:

store new bits = bin(0101011100110101);

Convert to float

float(<value>)
flt(<value>)

Convert to integer

integer(<value>)
int(<value>)

Value types and conversions

Values are integers, floats, strings, booleans, selectors (like @e[type=pig]) and text styles. Integers stay integers until a float is involved.

  • Strings can use "..." or '...'.
  • string()/str() turns any value into text. Floats are rounded to 10 decimal places, so sin(30) shows as 0.5.
  • boolean()/bool()/booleanState() accept only 0, 1, "true" and "false".
  • bin()/createBin() keeps a literal like bin(0101) as written. It turns integers into base 2 and text into the bits of its UTF-8 bytes.
  • integer()/int() drops the decimals of a float, reads a string of 0s and 1s (longer than one digit) as binary, reads other numeric strings as numbers, and turns booleans into 1 or 0.
  • float()/flt() reads numbers, numeric strings and booleans.

Boolean values

Plain true and false values are written <true;> and <false;>. The semicolon inside them doesn't end the statement. Writing a bare true or false is an error.

store new open = <false;>;
store set open = <true;>;

Data structure creation

Lists

Creation

Lists can be created in the same way variables are created, but with {} instead of values:

store new fruits = {apple, banana, FOOTCHEESEDEVICE};


Note

The items within a list can be of any combination of data type, which is automatically determined. This can be overridden with the data format converters [see above].

Modification, indexing [unresolved: this should be one heading smaller]

You can append items to a list by using:

store myList append {foot, cheese, fungus};
//the script above appends the 3 items to the end of the list

You can also insert items within a list by specifying the line to insert it to, which must be lesser than or equal the length of the list:

store myList append(5|6) {foot, cheese, fungus};
//the script above inserts the 3 items inbetween items 5 and 6 in the list

Item can be read from a list with the i (index) value:

store new item = mylist[3];
//the index is within the square brackets

Items can also be voided (deleted) from a list:

store myList void {[3], foot}
//this script voids item 3 and all occurences of "foot" within myList.

Note

All item indexes to void are always encased in [] and the list is stagnant until this script is finished, meaning that the values are not shifted forward to replace the null gap until all parts of the void are executed.

The length of a list can be fetched with len():

store new myListLength = len(myList);
//len() outputs a integer

Variables

Creation

Variables are created using store new <varname>=<init_value>;. Multiple variables can be created with the same value using store new <varname>, <varname>=<init_value>;.

Replacing a variable

A variable's value and kind can be replaced in one step by using the following:

store set <varname> as <value>;

Example:

store set cheese as "brie";
Modification

Existing variables are modified with the command store set <varname>=<float/int/bool/str_value>;. Variable values can be manipulated by using alter commands below. Note that once a variable is created, a conversion [see also: Input formatting] must be used to change the data set type, e.g., float, boolean, string... Spaces around the operators are optional.

Change by 1
store set <varname>++;
Change by -1
store set <varname>--;
Addition
store set <varname>+<val>;
Subtraction
store set <varname>-<val>;
Multiplication
store set <varname>*<val>;
Division
store set <varname>/<val>;

If you would like to retrieve the remainder of the division statement you can use

store set <varname>/%<val>;

Special operators like sqrt and cosine are in the Mathematical operators section.

Variable rules
  • $name anywhere in a command is replaced with the variable's value, for example tp @p $x 64 $z;. Inside values (after =, in if comp, in function brackets) the $ is optional.
  • Quoted strings in values keep $name as plain text, so join text with +: store new greeting = "Hello " + $name;.
  • Variable names start with a letter or _ and contain only letters, digits and _.
  • store new on a name that already exists replaces it with a yellow warning.
  • store set on a name that doesn't exist gives Error: Undefined data structure(s), except store set <name> as <value>;, which creates it.
  • store set <name> = <value>; must keep the same kind of value: integers and floats mix freely, but storing a string in a number needs a conversion like str(...). store set <name> as <value>; replaces the value and its kind without a conversion.
  • ++ and -- only work on numbers. + on a string joins text.
  • Variables last for the whole run, including the timers and event blocks that run started, so they can keep counting between ticks. Each new run starts with no variables.

Text styles

A text style is stored like a variable, from the same JSON /tellraw takes, and is put into commands with $name:

store new font(warning) as {"text":"WARNING!","color":"red","bold":true};
tellraw @a $warning;
store new message = font($warning, "Run!"); // same style, different text
tellraw @a $message;

The JSON is checked when it's stored, and an invalid text component is an error. store set font(<name>) as {...}; changes a style, or creates it if it doesn't exist.

Mathematical operators

Mathematical operators can be used to add, subtract, multiply, divide, square root, power, factorial, sin, cos, tan, inverse sin, inverse cos, inverse tan, log, and inverse log valid format variables, floats, and integers.

Addition

<val1> + <val2>

Subtraction

<val1> - <val2>

Multiplication

<val1> * <val2>

Remainderless division

<val1> / <val2>

Division by 0 results in a output of 0.

Remainder fetch

<val1> /% <val2>
<val1> mod <val2>

Logarithmic operations

Invalid operator syntax is a syntax error, and an input that isn't a number gives Error: Unexpected data type in input. A number outside what the function accepts gives NaN or an infinity, for example sqrt(-1) is NaN and log(0) is -Infinity.

Log
log(<val>)
Inverse log
log^(<val>)
Cosine
cos(<val>) //shorthand
cosine(<val>)
Inverse cosine
cos^(<val>) //shorthand
cosine^(<val>)
Sine
sin(<val>) //shorthand
sine(<val>)
Inverse sine
sin^(<val>) //shorthand
sine^(<val>)
Tangent
tan(<val>) //shorthand
tangent(<val>)
Inverse tangent
tan^(<val>) //shorthand
tangent^(<val>)
Square root
sqrt(<val>) //shorthand
sqaureroot(<val>)

Extra math functions

  • squareroot() also works, as well as the spelling above.
  • Powers use ^: 2 ^ 10. Factorials use fact(<val>) or factorial(<val>), for whole numbers from 0 to 20.
  • Angles are in degrees, like Minecraft's rotations. The ^ versions are the inverses (sin^(0.5) is 30) and also give degrees.
  • log() is base 10, and log^() is 10 to that power.
  • Order: brackets, then a leading -, then ^, then * / /% mod, then + -, then comparisons. This makes -2 ^ 2 equal to 4.
  • Dividing two integers gives an integer with no remainder, rounding down. Dividing by 0, including /% and mod by 0, gives 0.

Random value

Random inclusive values can be generated in ComScript with the following syntax.

Integer example:

random.randint(<min>, <max>)

Non-inclusive values can be generated using:

random.n.randint(<min>, <max>)

Random floats with a determined fix/round can be generated using:

random.<fix length>.rand(<min>, <max>)

Random value ranges

random.n.randint(1, 6) leaves out the maximum, so it gives 1 to 5. random.2.rand(0, 1) gives a float rounded to 2 decimal places.

Comments

Single-line comments use //. Multiline comments use // "text".

// this is a single-line comment

Multi-line comments

The multi-line form, // "text", continues until the closing quote. Anything after the closing quote is read as script, so a single-line comment shouldn't start with a quote.

// "this is a multi
line comment"

Chain commands

Commands can be chained with a semicolon:

fill ~ ~ ~ ~3 ~3 ~3 stone; fill ~-3 ~-3 ~-3 ~ ~ ~ stone;
Semicolons between commands

A newline alone doesn't chain commands: every statement needs its semicolon, even on its own line. Several statements can share a line. A statement can continue over several lines inside brackets or a string.

fill ~ ~ ~ ~3 ~3 ~3 stone;
fill ~-3 ~-3 ~-3 ~ ~ ~ stone; say done;

Execute commands

For execute commands, the as, at, in, align, anchored, positioned, rotated, facing, if, unless, run, and store subcommands follow the word execute. Example:

execute at @p run summon minecraft:pig;
Subcommands
As

The "as" subcommand is a sub argument used to execute a script as a certain entity.

Example:

execute as <entity selector> run {
    <script>
}
If

The "if" subcommand has a sub argument: comp. Comp is used to compare values.

if comp <value1> <operator> <value2>
Run subcommand

Instead of running one command, the run subcommand can run a chain, notated by braces. It can also run a single command normally.

execute at @p run {
    // Run a chain of commands
    summon zombie ~ ~2 ~;
    execute at @e[type=zombie] run summon lightning_bolt;
}
// Run one command
execute at @p run summon zombie ~ ~2 ~;
Execute and run blocks
  • Minecraft's execute subcommands need the word execute in front. A bare Minecraft if or unless is an error that shows the corrected line.
  • if comp and unless comp can be written on their own or mixed with execute subcommands. The operators are == (or =), !=, <, >, <= and >=.
  • Every if comp and unless comp on a statement is checked first, once, before the execute subcommands, and all of them must pass. To compare something for each entity, put the check inside the block, as in the example below.
  • Each value in a comparison is one word. A value with spaces goes in brackets: if comp ($a + 1) > 2 run say yes;.
  • A chain after run goes in braces, not parentheses, and each statement inside ends with a semicolon. Using parentheses is an error. A single command after run needs no braces.
  • The block runs once for every entity or position the subcommands reach, in order with the statements around it.
execute at @p run summon pig;
store new score = 10;
if comp $score >= 10 run say You win;
execute as @a at @s run {
    if comp getHealth(@s) < 5 run {
        effect give @s regeneration 5;
        say low health;
    }
}

Areas

Areas also known as <range> specifies a collection of blocks, which are listed and can be used for multiple purposes, including for scripts that look for blocks. An area has a max containing size of 5041 (712) blocks, which may be overriden but can get quite laggy. In order to differentiate areas from keywords, all areas start with the "#". This tells ComScript the following characters are for areas. Areas can be created by specifying 3 starting locations and 3 ending locations:

#area(x, y, z, x1, y1, z1)

for blocks.minecraft:cobblestone in #area(0, 0, 0, 20, 20, 20) {
    //"this script segment checks for any cobblestone within 20 blocks of the postive-positive 
    quadrant."
for blocks.minecraft:cobblestone in #area(~, ~, ~, ~20, ~20, ~20) {
    //"this script segment performs the same action as the script above, but is relative to the 
    execution location"

The second set of locations can also be relative to the first set, by using the dx, dy, and dz specifiers:

for blocks.minecraft:cobblestone in #area(0, 0, 0, dx = 20, dy = 20, dz = 20) {
    //"dx, dy, and dz are floats"

Note

There must be a space between the equal symbol, deviation specifier, and float.

#areas can also be stored lists, where it just outputs all blocks in order from execution pattern:

store myList append #area(0, 0, 0, 20, 20, 20);

Note

No curly brackets are needed, as if they are added, then an error would occur since ComScript would try to append all the contents of #area in a single item within the list, which is not possible.

Repeating for each iterator

ComScript allows for for i in... scripts by using iterator scripts, which come in the following types:

  • for <entity> in <range> with exc <opt: pattern> [see also: ranges]
  • for <block> in <range> with exc <opt: pattern>
  • for index in <list>
Each for i in... executes the nested script for each item within the range, which can be a <range>, <integer>, or <list> data type. For example in the script
for @entity.minecraft:pig in #area(~-10, ~-10, ~-10, ~10, ~10, 0) {
     console.log("pig in the perimeter of a 20-block cube around the scripter!");
}

first detects for minecraft:pig within the relative location defined 20-block cube surrounding the Scripter or execution location. Then, for each Pig in the cube, the nested script is triggered as the Pig, which also changes the execution location locally (only for scripts nested within the for script.

Triggering "as" a element (such as entity or block) also brings endemic keywords, which only work when executing as a certain element.

Event sensing

Scripts executing conditionally during an event or every tick can be started with *{<script>} to execute every tick and *<event namespace>{<script>}.

Example:

*blockEvent.blockBreak{
    execute at @a run summon minecraft:lightning_bolt;
}

Supported events

ComScript supports these events:

*blockEvent.blockBreak{ } // a block is broken
*blockEvent.blockPlace{ } // a block is placed
*playerEvent.join{ } // a player joins
*entityEvent.death{ } // an entity dies

An event block runs at the event's position, as the entity that caused it (for a death, the entity that died). It can read $event_x, $event_y and $event_z, plus $event_block (for block events) or $event_entity (for join and death).

Timers

*{ } runs every tick. *N{ } skips N ticks between runs, so it runs every N + 1 ticks: *1{ } is every other tick and *19{ } is once a second. N can be up to 9 digits long. A timer keeps repeating, and the lines after it in the script run straight away.

store new seconds = 0;
*19{
    store set seconds ++;
    title @a actionbar "$seconds s";
}

Timers and event blocks keep running until the script is run again, Stop is pressed, or the Scripter is broken or unloaded. The terminal shows what the script is listening for.

Keywords

Selectors

Use Minecraft's selectors (@p, @a, @e, @n, @r, @s), which work everywhere.

Variables

Boolean

LoadChunk(x,y,z)? // check if the chunk is loaded

Checking chunks and players

The ? is optional, and Online(Steve) doesn't need quotes. store.global set excrd works as described under Execution marker.

Native fetchers

53 functions that read the world, usable anywhere a value goes. Entity arguments take a selector, a player name or a variable holding either. Position arguments are x, y, z. To use a fetcher's result in a command, store it first: store new x = getX(@p); tp @p $x 64 0;.

// Entities (first entity matched)
getDir(e) getPitch(e) // facing yaw and pitch, degrees
getDeltaX(e) getDeltaY(e) getDeltaZ(e) getSpeed(e) // motion
getX(e) getY(e) getZ(e)
getHealth(e) getMaxHealth(e) getArmor(e)
getFood(player) getXpLevel(player) getGamemode(player)
getItem(e, slot) // item count in the slot
getItemName(e, slot) // item id in the slot
getName(e) getType(e)
getCount(selector) // how many entities match
getDistEntities(e1, e2)
isAlive(selector) isOnGround(e) isInWater(e) isSneaking(e)
isSprinting(e) isOnFire(e) isPlayer(e) hasTag(e, tag)

// Positions and terrain
getDistVector(x1, y1, z1, x2, y2, z2)
getTemperature(x, y, z) getPrecipitation(x, y, z) getBiome(x, y, z)
getBlock(x, y, z) getLight(x, y, z) getRedstone(x, y, z)

getClimateTemperature(x, y, z) getHumidity(x, y, z)
getContinentalness(x, y, z) getErosion(x, y, z)

The slot is a number, and the tag in hasTag is quoted or a variable. getTemperature, getPrecipitation, getBiome, getBlock, getLight, getRedstone and getHeight need the chunk to be loaded. Fetcher names are not case-sensitive.

Example:

if comp isDownfall == <true;> run say It is raining;
