ComScript

[UNRESOLVED] The source marks the ComScript name as subject to change and contains unresolved technical placeholders; review them before treating this page as final.

ComScript is a coding language based on Minecraft Commands that eliminates the need for long chains of Command Blocks. ComScript can be natively and directly executed in [read also: lobby] the admin lobby or by typing scripts into the Scripter block.

Errors

Errors due to syntax or any other reason when the script is run are shown in the native terminal located at the bottom of the UI. All errors are red text, warnings as yellow text, and logs as white text.

Error: Undefined data structure(s)

This error appears when undefined variables, arrays, lists, or dictionaries are used.

Error example:

Error: No mandatory execution marker found

This error appears when a selector requiring an execution marker does not have a global marker to fetch from. This can trigger a domino effect of errors since the invalid selectors output null, which may not be compatible with the data type where the selector is used.

Error: Unexpected data type in input

This error occurs when an incompatible data type is used in an input.

Error example:

;

The semicolon is an operator for integers and floats only.

Technical details

Terminology

Relative location selectors

Relative location selectors include any selectors that are location or distance based, meaning that they must have a starting point of execution. These include:

  • @p
  • @n
  • @s (Education Edition only)
  • @c

If no execution marker is included, then it will error and output null at any use instances.

Native console

The native console is the built-in executor within the esc menu.

Token

A token is any symbol, symbolized, or packaged string that can be used in a value type.

Command selector standardization

All commands with selectors now follow the structure below:

<command namespace> <selector> <action/input> <opt: attributes, booleans, conditions, etc.>

Execution pattern

Selector fetch pattern

If a selector is distance based, such @p (closest player), then the code scans in a spiral pattern in 1x1x1 chunks looking for an entity with the valid conditions for the selector.

Example:

Assume that an entity with the correct conditions is being searched for with a relative location selector. The block Chunks are labeled by scan order. The scan terminates and returns the result after the entity is found.

           1  2  3  X  13
              8     4
          7  6  5
          X = execution marker location

[see also: Custom execution pattern]

Quotations

Quotations in comscript are unidirectional, meaning that they do not directionally encapsulate text.

Example:

Serif: ""

ComScript: ""

*The two quotes above should look identical but different from Serif, if they don't then your browser may not support unidirectional quotations.

Execution location auto-assumption key

Commands executing without a specified location(specified via the marker keyword)are executed based off of the following rules:

If the script line is encapsulated by a *{} condition statement with a location specifier, then it is executed there.

If no specified location is fetched from the previous condition(s), the execution marker (if one was fetched correctly) becomes the native execution location. If no location is fetched, and a script is executing from a Scripter block, valid selectors execute from the Scripter's location:

  • @p (for locational relative/proportional selectors such as closest player/entity, this is relative to the location of execution) [property P1]
  • @e [see property P1]
  • @s [see property P1]
  • @n [see property P1]

If the script is executed directly from the native console and no location is defined by the previous rules, the script executes globally, causing a syntax error in any relative location selectors.

Syntax

Definers [unresolved: better name]

local:

The local definer causes any modifier keyword to become a local action. Local actions only perform the modifier within said file or, when encapsulated within a flow-control string, only within that segment unless otherwise stated with global:.

Example:

local:mark add @r.cache-once mobile

global:

.get-once

The .get-once modifier is used on inputs that require a random number generator. .get-once can be used if a event/target entity is randomized, as the .get-once prevents a random number generator from functioning normally.

.lock-element

Custom execution pattern

Custom execution patterns can be defined using the pattern keyword. For a definition and explanation on execution patterns, see Technical details: Execution pattern.

Example:

local:pattern set r-spiral; //sets pattern to spiral

Valid built-in execution patterns:

  • l-spiral: clockwise spiral
  • r-spiral: counterclockwise spiral
  • rand-<radius applier>: randomized
  • top-r-bttmscan: start from top right downwards
  • top-l-bttmscan: start from top left downwards
  • bttm-r-topscan: start from bottom right upwards
  • bttm-l-topscan: start from bottom left upwards
  • odd-checker: first from top left to bottom odd tiles then even tiles
  • even-checker: first from top left to bottom even tiles then odd tiles

Execution marker/location

Execution markers mark where the script would start executing if you would like to override the location of where the scripter block is placed or specify the location of where the script is executed if written in the native console. Selectors that are location-based (nearest entity, etc.)scan in a spiral pattern clockwise starting northwest of the marker to search for valid selectors; see Selector fetch pattern. Execution markers can be defined using the following:

mark add<location (x y z)> <mobility>;

Mobile relative execution markers

Relative execution markers move depending on the base selector and the spacing. These allow scripts to execute depending on the mobile selector; which means that you can have scripts executed at a specific tagged sheep for example. If a script is a macro-script

(meaning executed process takes >2 ticks) then the script execution location stays at the

Syntax:

mark add relative <base selector> <tilde defined relative location>;

Example:

mark add relative @e[type=sheep, tag=cheese] ~~10~;

Charset

Character sets and character operations can be changed manually by using the charset keyword. Charset acts as the <meta> tag in HTML. Charset has the following valid sub- keywords:

Charset store

Charset store changes the current charset.

Example:

charset store UTF-8

Valid charsets for comscript include

  • UTF-8
  • US-ASCII
  • ComScript-EN (default)
  • ComScript-zh-CN (modified in language settings)
  • Comscript-hi-IN (modified in language settings)

For more information, see Charset token (custom substitution).

Charset token (custom substitution)

For convenience reasons, if you would like to create your own token substitution token then you can use the following. The example below a fatal error will occur if you store it as a pre-existing token.

Example:

charset token store &dollar; = &s;;

One token is the abbreviation, and the other closes it.

Input formatting

Inputs in comscript can accept the following formats

  • Unicode — expected formatting: <value>
  • String — expected formatting: <value>
  • Binary (useful for raw files) — expected formatting: <complex value>
  • Boolean — expected formatting: <conditional statement>
  • Float — expected formatting: <value>
  • Integer — expected formatting: <value>
  • Packaged Lists — expected formatting: <complex value>
  • Blockstate — expected formatting: <state>
  • Entity — expected formatting: <name>
  • Item — expected formatting: <item name>
  • Coordinate — expected formatting: <x> <y> <z>
  • Custom format

If you want to change/define the format of a variable or value, you can use the following:

Convert to string

string(<value>);
str(<value>);

Convert to entityrange

Entityrange is used for entity iterators.


    entityrange(<entity list>)

Convert to boolean

Only 1-digit binary integers, and strings with boolean names can be converted.

boolean(<value>);
bool(<value>);
booleanState(<int0-1>)

Convert to binary

Anything can be converted into binary, as it is the raw data type.

bin(<value>)
createBin(<value>)

Example:

bin(0101011100110101)

Convert to float

float(<value>)
flt(<value>);

Convert to integer

integer(<value>)
int(<value>);

Package a list

Packaging a list allows for mixed values to be combined and still be able to be extracted from a different source.

Syntax:

pack.push(<listname>);

Example:

store set myVar= int(String);

Custom type

Custom types can be stored as a list with all valid strings and/or characters listed within the built-in list.

Example[UTF-8]:

The statement above would declare all strings or characters within the parentheses to be the only valid tokens in that data format.

Function block

Function blocks are a new block that creates global functions applicable across all command blocks. When opened, the player assigns a function name and can be assessed with the keyword.

<function name>(<function variables, Booleans, etc.>){
    <function contents>
}

Variables, lists, arrays, and dictionaries created within a function are all stored locally, meaning that you cannot acsess them unless you make them global via

global(<namespace>);

If you would like to turn a global data structure back to local and change all outside instances of the data structure to null, then you can use the following:

local(<namespace>);

Entity Range Iterators

Entity range iterators are used to iterate over a range of entities that can be defined using the syntax below:

for @client.entityiterator in <entity range selector>{
    <repeat script>
}

Example:


    global(return @getcubeentities(5, 5, 5) as @entities.cube);
    global(return filter.insubtypeof(minecraft:players) as (playerlist{}));
    for @client.entityiterator in entityrange(playerlist{}){
        // script contents
    }

Data structure creation

Variables

Creation

Variables are created using store new <varname>=<init_value>;. Multiple variables can be created with the same value using store new <varname>, <varname>=<init_value>;. Global variables (which are built in) can be fetched with return.global<varname>; or return.global <varname> as <varname temp>;.

Formatting

Variables can be created with a preset format (see Input formatting) by using the following:

store set <varname> as <format code>;

Example:

store set cheese as);

Note that variables made with a preset format can still be modified using input formatting syntax.

Modification

Existing variables are modified with the command store set <varname>=<float/int/bool/str_value> Variable values can be manipulated by using alter commands below. Note that once a [read: Input formatting] variable is created, a modifier command must be used to change the data set type, e.g., float, boolean, string... A space must be used between variables and operator keywords.

Change by -1
store set<varname>++;
Change by 1

And they can also be modified using augmented expressions:

store set<varname>--;
Addition
store set<varname>+<val>;
Subtraction
store set<varname>-<val>;
Multiplication
store set<varname>*<val>;
Division
store set<varname>/<val>;

If you would like to retrieve the remainder of the division statement you can use

store set<varname>/%<val>;

Special operators like sqrt and cosine section.

Execution range

Execution range is a variable that determines the area that the script applies to and executes as. For example, if a script with an execution range of a circle with a radius of 5

foot is outside of the circle, then the script will return null.

Random value

Random inclusive values can be generated in ComScript with the following syntax.

Integer example:

random.randint(<min>, <max>)

Non-inclusive values can be generated using:

random.n.randint(<min>, <max>)

Random floats with a determined fix/round can be generated using:

random.<fix length>.rand(<min>, <max>)

Comments

Single-line comments use //. Multiline comments use //[text].

Chain commands

Commands can be chained with a newline:

fill ~~~~3~3~3 Stone
fill ~-3~-3~-3~~~ Stone

They can also be chained with a semicolon:

fill ~~~~3~3~3 Stone; fill ~-3~-3~-3~~~ Stone

Execute commands

For execute commands, the execute part is erased, and the as, at, in, align, anchored, positioned, rotated, facing, if, unless, run, and store become the command itself. Example:

execute at @p run summon pig
at @p run summon minecraft:pig
Subcommands
As

The "as" subcommand is a sub argument used to execute a script as a certain entity.

Example:

as <entity selector> run {
<script>    
}

The "as" subcommand comes with certain selectors that are given, including:

  • Event/Target Entity: the current entity executed as.
  • Source Entity: the trigger entity, for projectiles and items only.
  • Immediate Source Entity: the immediate trigger entity [for example, the projectile that just impacted a entity selector]
If

The "if" subcommand has a new sub argument: comp. Comp is used to compare values.

if comp <value1> <operator> <value2>
Run subcommand

Instead of running one command, the run subcommand can run a chain, notated by parentheses. It can also run a single command normally.

at @p run (
    // Run a chain of commands
    summon zombie ~~2~
    at @e[type=zombie] run summon lightning_bolt
)
// Run one command

Event sensing

Scripts executing conditionally during an event or every tick can be started with *{<script>} to execute every tick and *<event namespace>{<script>}.

Example:

*worldEvent.blockBreak{
    at @a run summon minecraft:lightning_bolt;
}

Additional syntax and execution

Header

The header file in a ComScript file is essential for linking all of the projects together. Header files declare execution details globally unless stated otherwise in a file. Header files support the following keywords:

  • mark
  • return
  • void
  • queue
  • provide
  • Global functions
  • Global objects

Execution Priority

Execution priority is an integer ranging from 0 to the number of ComScript files in a project that determines when a file should be executed while in queue.

Queue (execution priority)

The queue keyword is a header-file-only keyword used to determine the right-of-way when two files are executed simultaneously. Queue provides an index for each file, ranging from 0 to the number of files in the project, ranking the priority of the files. A lower queue index means higher priority.

Auto queue is a built-in queue configuration that uses the following to determine a file's priority:

  • If a file has runtime keywords that take longer than 1 tick to execute: Priority 1
  • If a file fetches from another source and the opposing file does not need external help: Priority 2
  • If a file is executed first: Priority 3
  • If the file has a name higher in the alphabet when in alphabetical order: Priority 4

If any conditions above are met, return(execute);.

Queue syntax:


store new queueList = {};
private class queue {
    queue add <highest priority file href>;
    queue add <mid priority file href>;
    queue add <low priority file href>;
    return(getqueue) as queueList;
}

Void functions

If the function being created does not return a value, use this syntax:

void <function name>(<function variables, booleans, etc.>){
    <function contents>
}

Classes

Classes are an important part of ComScript and object-oriented programming in general. Classes can be named and specified in a header file for script execution modifiers such as execution location and priority. Classes can be created with the following syntax:

public <class name> {
    <class contents>
}

Subclasses

Subclasses can be created within a larger scope class to apply a modifier to a specific section within the scope class. Subclasses can be created with the following syntax:

public class <subclass name> extends <scope class> implements <greater scope class (optional)> {
    <subclass contents>
}

Grant Private Fetch Access

If you have a private element that you would like to give another file permission to fetch from, use the following syntax to allow localized fetching:

override private(<private object namespace>, <href of file grant permission>, <optional: this file>);

This must be implemented before the line where the other file fetches, and the granting file must have a higher priority value in the header file.
