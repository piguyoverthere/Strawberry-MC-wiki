Standardized grammar conventions for wiki pages

Forced DJABBAC style 

If you are bad at naming things, use the forced DJABBAC style and give all your things [unnamed n] tags instead of naming yourself (to prevent rejection) 

Headers [IMPORTANT] 

When writing your own section, remember to use the correct header format and make sure your headers are not interfering with other people’s sections. Another thing to keep in mind is to capitalize your heading correctly such as using More About French Fries instead of More about french fries. Note conjunctions in titles such as is, and, in, or of do not need to be capitalized. 

Headers in a document should go like this (in order): 

  • Heading 1: Collection of things (You should not need to use this while writing unless you are starting an entire new section agreed upon by everyone). 

  • Heading 2: most of the time will be the main title or topic of what you're adding to this document. Make sure that you put your section in the correct super-category (heading 1’s), such as {Rendering}, {Biome related}, and {Standalone features}. 

  • Heading 3: divisions of what you're adding to your document, for example you are adding french fries, then you would want to divide it into Obtaining, Effects, and more. 

  • Heading 4: subdivisions of your divisions 

  • Heading 5: even smaller sections of your subdivisions 

  • Heading 6: Although rare, sometimes you must use heading 6. 

  • Bullet points or number lists: these are on the same level of depth as heading 6 but are a more organized way to list lots of content. 

Dividing sections 

When dividing and naming your section, it is important to remember to use specific titles, for example if you are creating a section on french fries, do it like this: 

French Fries [heading 1] 

[description] 

Potato French Fries [heading 2] 

[description] 

Sweet Potato French Fries [heading 2] 

[description] 

NOT LIKE THIS: 

French fries [heading 1] 

[description] 

Potato [heading 2] 

[description] 

Sweet Potato [heading 2] 

[description] 

We do this so that when people are using ctrl+F to search this document, they are not getting confused about a section on sweet potatoes in the middle of nowhere. 

Furthermore, try to divide your sections as less as possible, but still avoid having your page be a singular brick of text.

Descriptiveness, common grammar

When writing each paragraph, try to be as descriptive as possible, avoiding for example saying "causes the player to die", instead use "causes the layer to catch on fire for X seconds and take Fire damage". You don't have to be descriptive when writing the summary in the wrapper page, which for example there is a The Void [dim] page which contains a quick summary of Voidstone, and a Voidstone [technical] page with a in-depth description of Voidstone that specifies the code clearly, including a table that specifies attributes:

  • Blocks: Resistance (explosion resistance), Hardness (how long it takes to mine), Bounding box, Waterloggable, Noteblock sound, Map hex color.
  • Biomes: Temperature (determines downfall), Generation conditions, Downfall chance, Fog hex, Vegetation tint hex, Surface builder block, Water fog hex, Water tint hex.
  • Entities: Hostility, header named Behavior (American spelling), header named Morphology (description on visuals).

CAPITAILIZE YOUR NOUNS

I have had to remind the editors SO many times of this (especially SOME of you guys) to capitalize all nouns originating from Strawberry MC or Minecraft, such as capitalizing Sand, Wisp, Bamboo... An easy way to remember this is to ask yourself if the noun refers to a specific something, such as Sand in Minecraft, but not any sand in real life. If you see any of these mistakes, I encourage you to fix them and commit.

Sentences

Do not start your sentences with fractured beginnings, such as Also (replace with Furthermore, Additionally, etc.), And, So, Or, But, or other conjunctions. Either merge the sentence with the previous one if the topic is close enough and/or the 2nd sentence is a fragment or replace conjunction with something more formal.

Additionally, avoid using "it", "they", "them", "he", "she", "her", "his", or other pronouns. Instead, just use the name of the item, such as Wisp instead of "it".

Tense and Subject 

This document officially uses past tense and uses “the player” to refer to the player. 

Symbols and Abbreviation 

On the document, the use of symbols like “&” is not allowed, as they are only used when conjoining 2 different married couples’ names. 

Comments [dev] 

When changing or adding anything, add a comment “clogpost: made changes” so that a simple scroll through the doc will tell you the most recent additions 

Creating your own page

Press + New page at the top of any page, give the page a title and write it. Save edits keeps your work in this browser, and Commit to GitHub publishes it. Follow the conventions above while writing.

  • + Table inserts a table. While the cursor is in a table, + Row, − Row, + Column and − Column appear in the editing bar.
  • + Recipe inserts a crafting recipe, and + Blocks inserts a diagram made of blocks, one row per line. Click either one while editing to change it.
  • + Code box inserts code. Press the down arrow at its end, or Enter twice, to continue in normal text.
  • If a page is missing information, use More → Mark as unresolved so it shows up on the To Do list.
  • Names of Strawberry MC elements link to their pages by themselves, so there's no need to link them by hand.
  • To comment on part of a page, select the text and press Comment. Typing @ and a name assigns that person a task.
