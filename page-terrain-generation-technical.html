Terrain Generation [technical]

The mod's Terrain Generation code has three parts: adding custom biomes to the Overworld biome source, adding their surface rules, and editing the Overworld density functions. The Void dimension's terrain is separate and is described on The Void [technical].

Adding biomes to the biome source

BiomeSourcePresetMixin targets MultiNoiseBiomeSourceParameterList.Preset. When a preset with the ID minecraft:overworld or minecraft:nether is constructed, it wraps the preset's provider so the original list passes through StrawberrymcModBiomes.adaptPresetParameterList.

this.provider = new MultiNoiseBiomeSourceParameterList.Preset.SourceProvider() {
	@Override
	public <T> Climate.ParameterList<T> apply(Function<ResourceKey<Biome>, T> lookup) {
		Climate.ParameterList<T> originalList = existingProvider.apply(lookup);
		return StrawberrymcModBiomes.adaptPresetParameterList(idArg, originalList, lookup);
	}
};

adaptPresetParameterList returns the list unchanged until FMLCommonSetupEvent has set BOOTSTRAP_VALIDATION_PASSED. After that, the Overworld list goes to modifyOverworldParameterPoints, and the Nether list is returned unchanged.

Claiming climate boxes

SurfaceBiomeDepthMixin injects at the return of modifyOverworldParameterPoints. It first appends strawberrymc:ocean_abyss at depths 0 and 1, with temperature -0.45 to 1, humidity -1 to 1, continentalness -1.05 to -0.7, erosion -1 to 1 and weirdness -1 to 1.

It then processes its SURFACE_BIOMES list, alpine_meadow and ocean_abyss. For each box a listed biome owns, the subtract method cuts that box out of every other surface entry, splitting the entry dimension by dimension into the pieces outside it. isSurface limits this to entries whose depth is the single point 0 or 1, so cave biomes keep their ranges. The source comment gives the reason: vanilla already covers every climate value, so a custom biome would otherwise only tie with a vanilla one.

Climate.Parameter[] rest = from.clone();

Surface rules

At ServerAboutToStartEvent, StrawberrymcModBiomes.onServerAboutToStart walks the LEVEL_STEM registry. For every Overworld or Nether stem using a NoiseBasedChunkGenerator, it stores the dimension type on the generator's settings through StrawberrymcModNoiseGeneratorSettings.

NoiseGeneratorSettingsMixin wraps surfaceRule with MixinExtras @WrapMethod. If a dimension type was stored, the original rule is passed to adaptSurfaceRule, which only changes it for the Overworld.

injectOverworldSurfaceRules places the custom rules first. If the original rule is a SequenceRuleSource, its entries are appended after them; otherwise the whole rule is appended. Custom biomes therefore resolve before any vanilla rule.

preliminarySurfaceRule applies above the preliminary surface. anySurfaceRule applies from 5 blocks above the bottom of the world to 5 blocks below the top, which lets a cave biome receive surface blocks underground. Both use stoneDepthCheck(0, false, 0, FLOOR) for the ground and underwater blocks, with waterBlockCheck(-1, 0) choosing between them, and stoneDepthCheck(0, true, 0, FLOOR) for the underground block.

Overworld density functions

The mod overrides two files under data/minecraft/worldgen/density_function/overworld/: offset.json and factor.json. In each, the vanilla expression is kept inside a minecraft:add, under flat_cache and cache_2d, whose second argument is a spline on minecraft:overworld/continents. All derivatives are 0.

Outside the range -1.1 to -0.68 the spline adds 0 and the vanilla terrain is unchanged. Inside it, the terrain is lowered and flattened, forming the basin used by the Ocean Abyss. The biome and the feature that floods it are on Ocean Abyss [technical].
