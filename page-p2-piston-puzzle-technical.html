P2 Piston Puzzle [technical]

Overview

The P2 piston puzzle is a tree of jigsaw pieces stored in a built-in datapack. Its template pools and pieces are generated by a Python script, java/tools/monument_puzzles/gen.py. Pieces edited in game are copied back into the pack by java/tools/monument_puzzles/import.py. The pieces are assembled by the strawberrymc:monument_puzzles/p2_test structure, which no structure set references, so it appears only when placed by command. For the building that surrounds these puzzles, see Ocean Monument.

Datapack

MonumentPuzzlesPack listens to AddPackFindersEvent and registers src/main/resources/monument_puzzles. Keeping the files in their own pack means MCreator never regenerates or removes them.

private static void addPack(AddPackFindersEvent event) {
	event.addPackFinders(Identifier.fromNamespaceAndPath("strawberrymc", "monument_puzzles"), PackType.SERVER_DATA,
			Component.literal("Strawberry MC monument puzzles"), PackSource.BUILT_IN, true, Pack.Position.TOP);
}

pack.mcmeta sets min_format and max_format to 101.1, with the description "Strawberry MC Ocean Monument puzzle jigsaws".

How the pieces join

Route doorways

Every route room is 16 wide, 12 tall and 16 deep, entered through its north wall and left through its south wall. doorway carves a 3x3 opening of water centerd on DOOR_X = 7, at y 1 to 3, with its jigsaw at the bottom middle and a waterlogged minecraft:copper_grate through the same wall.

def doorway(piece, z, outward, jigsaw_args):
    # 3x3 opening with its jigsaw at the bottom middle, and the pipe through the wall beside it
    for dx in (-1, 0, 1):
        for y in (1, 2, 3):
            piece.set((DOOR_X + dx, y, z), *WATER)
    piece.jigsaw((DOOR_X, 1, z), f'{outward}_up', final_state='minecraft:water', **jigsaw_args)
    # Left of the route: entering through the north wall heading south, left is east (+x)
    piece.set((DOOR_X + PIPE[0], 1 + PIPE[1], z), *GRATE)

PIPE is (4, 7): walking along the route, the pipe is always 4 blocks to the left of the doorway's jigsaw and 7 up. Because that offset is the same on every doorway, two connected rooms always have their pipes aligned.

Overlays

A sub-variant that only changes what is inside a room is an overlay: a template the size of the room's inside, attached through the floor-corner slot. Blocks not listed in a template are skipped when it is placed, which works like structure void, so an overlay leaves the room alone everywhere it has no block. The overlay's own jigsaw sits at (0, 0, 0) with orientation down_north and name strawberrymc:overlay. Its final state replaces that one corner block.

A sub-variant that changes a room's shape is a separate room in the p2 pool.

All names start with strawberrymc:monument/p2/. Sizes are width x height x depth.

Side rooms

The side rooms are 12x12x12 and stay dry. Each has the same shell materials as a route room, with air inside and:

  • Lava across x 1 to 10, y 1 to 2, z 1 to 10.
  • A dark prismarine landing filling (8, 1, 3) to (10, 3, 7), inside the door.
  • A dark prismarine chest platform filling (1, 1, 3) to (3, 3, 7).
  • A chest facing east at (2, 4, 5).
  • A 3x3 minecraft:stone_bricks blockade in the east wall at x=11, z 4 to 6, y 4 to 6.
  • A jigsaw at (11, 4, 5), orientation east_up, name strawberrymc:side_room_in, turning into stone bricks.
  • A sign at (9, 4, 5).

Pool entries use "override_liquid_settings": "ignore_waterlogging", so blocks in these rooms are not waterlogged even though the rest of the structure uses apply_waterlogging.

gen.py

Run python3 tools/monument_puzzles/gen.py from the java folder. The script holds the whole tree as Python data. It always rewrites pack.mcmeta, the pools and the test structure. A piece's .nbt is written only when that file does not exist, so rooms built and imported in game are kept. The flag --reset-placeholders rewrites every piece.

The script has its own minimal NBT writer, with no dependencies. Int and Byte subclasses mark tag types, and the output is gzip-compressed. A Piece holds a dictionary of cells from position to block name, properties and block-entity NBT. Its save method turns those into the structure template format.

palette, index, blocks = [], {}, []
for pos in sorted(self.cells):
    name, props, nbt = self.cells[pos]
    key = (name, tuple(sorted(props.items())))
    if key not in index:
        index[key] = len(palette)
        entry = {'Name': name}
        if props:
            entry['Properties'] = dict(props)
        palette.append(entry)
    block = {'pos': [Int(c) for c in pos], 'state': Int(index[key])}
    if nbt:
        block['nbt'] = nbt
    blocks.append(block)

import.py and the editing workflow

Structure blocks save into the world, under generated/strawberrymc/structure/monument. import.py copies from there into the pack.

python3 tools/monument_puzzles/import.py run/saves/<your world>

It walks the source for .nbt files only and skips any file that is byte-identical to the pack's copy (filecmp.cmp with shallow=False). For each file it copies, it prints copied monument/<name>. It finishes with N piece(s) updated. With --dry-run it prints would copy and N piece(s) to update and writes nothing. It exits with an error when the world has no saved monument pieces.

  1. In a creative world in the dev client, place a structure block in Load mode, enter a piece name such as strawberrymc:monument/p2/v1, and load it.
  2. Build over it, keeping the piece's size, the doorway jigsaws and their 3x3 openings, the pipe offset through each doorway wall, and any floor-slot jigsaw at (1, 0, 1) and side-door jigsaw.
  3. Switch the structure block to Save with the same name and size. Turn on "Include entities" for mobs, and give them PersistenceRequired:1b so they do not despawn.
  4. Run import.py from the java folder.

While in that world, the copy saved in the world is used in place of the pack's copy, so a piece can be loaded and saved repeatedly without importing each time. Overlays only need the blocks they change, with structure void everywhere else, because air would erase the room's own blocks.
