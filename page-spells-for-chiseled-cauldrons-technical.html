Spells For Chiseled Cauldrons [technical]

The spell vial in the mod is the Smite Vial (strawberrymc:smite_vial). Used on a Chiseled Cauldron, it strikes every other entity around the cauldron with lightning. See the main Spells For Chiseled Cauldrons page.

Smite Vial item

item/SmiteVialItem.java (element elements/SmiteVial.mod.json) extends Item and sets Rarity.UNCOMMON. It is registered in init/StrawberrymcModItems.java as smite_vial with a stack size of 64 in its element, and it is listed in the Ingredients and Combat creative tabs by init/StrawberrymcModTabs.java. Its model at assets/strawberrymc/models/item/smite_vial.json uses parent item/generated with the texture strawberrymc:item/smite_vial. The lang key is item.strawberrymc.smite_vial.

The element binds the procedure through its onRightClickedOnBlock field, and the generated useOn override forwards the clicked block position, the player and the held stack:

@Override
public InteractionResult useOn(UseOnContext context) {
	super.useOn(context);
	SmiteHandlerProcedure.execute(context.getLevel(), context.getClickedPos().getX(), context.getClickedPos().getY(), context.getClickedPos().getZ(), context.getPlayer(), context.getItemInHand());
	return InteractionResult.SUCCESS;
}

useOn returns InteractionResult.SUCCESS for every block, so the hand-swing happens on any right-clicked block, while the spell itself only runs on a cauldron.

SmiteHandlerProcedure

SmiteHandlerProcedure [raw] (element elements/SmiteHandler.mod.json) returns immediately if the entity is null, which covers a useOn call without a player. It then requires the block at the clicked position to be StrawberrymcModBlocks.CHISELED_CAULDRON. When that passes, it runs these steps in order:

  1. Plays item.bucket.empty at the cauldron in SoundSource.MASTER at volume 1 and pitch 1.
  2. Collects the entities in the strike volume, sorted nearest first, and strikes each one other than the user.
  3. Spawns the 36 angry-villager particles above the cauldron.
  4. Consumes one vial unless the user is a creative-mode player.

Strike volume and targets

The center is built from the clicked block's integer coordinates, so it sits on the block's lower north-west corner rather than its middle. The box extends 5 blocks in each direction from there (inflate(10 / 2d)), making a 10 by 10 by 10 cube. The query uses Entity.class with the predicate e -> true, so all entity types are targets, including items and other non-living entities. The list is fully collected with toList() before any bolt is spawned, so bolts created by the loop do not become targets.

final Vec3 _center = new Vec3(x, y, z);
for (Entity entityiterator : world.getEntitiesOfClass(Entity.class, new AABB(_center, _center).inflate(10 / 2d), e -> true).stream().sorted(Comparator.comparingDouble(_entcnd -> _entcnd.distanceToSqr(_center))).toList()) {

			_level.addFreshEntity(entityToSpawn);
		}

Each target receives a LightningBolt at the bottom center of the block it occupies, created with EntitySpawnReason.TRIGGERED, and the sound entity.arrow.hit_player in SoundSource.MASTER at the target's position.

Client and server handling

useOn runs on both logical sides, so the procedure branches per call: sounds use playSound(null, ...) on the server and playLocalSound on the client, while lightning and particles are limited to ServerLevel.

Particles

A local Angle variable starts at 0 and is passed to Math.cos and Math.sin as the X and Z spread of each sendParticles call, at a height of y + 1. It increases by 10 on each of 36 iterations. Math.cos and Math.sin take radians, so each step is 10 radians.

for (int _i1 = 0; _i1 < 36; _i1++) {
	if (world instanceof ServerLevel _level)
		_level.sendParticles(ParticleTypes.ANGRY_VILLAGER, x, (y + 1), z, 1, Math.cos(Angle), 0, Math.sin(Angle), 1);
	Angle = Angle + 10;
}

Consumption

The stack shrinks by one when the entity is not a Player in GameType.CREATIVE. Because this sits inside the cauldron check, right-clicking any other block leaves the vial intact.
