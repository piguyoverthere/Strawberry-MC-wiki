ComScript [technical]

This page describes how the ComScript interpreter is coded. For the language as a script writer sees it, see ComScript. The block that stores scripts, starts them and shows their output is covered in Scripter technical details.

Source layout

The interpreter lives in the io.github.strawberrymc.comscript package. It is written by hand and is registered from StrawberrymcMod with one call to ComScript.init.

FileResponsibility

Source to execution

  1. ScripterBlockEntity.run calls ComScriptParser.parse(script). The whole script, including nested blocks and every expression, is parsed before anything runs. The first SyntaxError ends the attempt.
  2. split cuts the source into Piece records (a line number and text) and drops comments.
  3. statement turns each piece into a Command, Store, Mark, Execute or EventBlock. Block bodies are parsed recursively by the same code.
  4. A new ComScriptRunner runs the list with a command source located at the Scripter.
  5. Timer and event blocks register listeners. Those listeners keep a reference to the same runner, so they share its variables.

Statement splitter

ComScriptParser.split is a single character loop that tracks the current line, the line a statement began on, and a bracket depth. At each position it checks, in order: comment, boolean literal, string, bracket, semicolon, newline, then ordinary character.

Comments

Two characters // outside a string start a comment. The loop skips any spaces after them. If the next character is a quote, the comment continues up to the next quote of any kind, across lines, and line numbers are advanced for the newlines inside it. If no closing quote exists, the comment runs to the end of the source without an error. Otherwise the comment ends at the newline.

Because the quote test only looks at the first character after //, a comment such as // "a" b ends at the second quote and b is read as code. Comments are removed at every bracket depth. Strings are jumped over as a unit, so // inside a string is safe, while an unquoted // in a command always begins a comment.

Strings and quotes

isQuote accepts the straight double quote and both curly double quotes, and they close each other. A single quote starts a string only when isStringStart finds it at the start of the text or right after one of space, tab, newline, :, [, {, (, = or ,, so the apostrophe in don't is ordinary text.

static int stringEnd(String text, int i) {
	char open = text.charAt(i);
	int j = i + 1;
	while (j < text.length()) {
		char c = text.charAt(j);
		if (c == '\\' && open == '\'' && j + 1 < text.length()) {
			j += 2;
			continue;
		}
		if (open == '\'' ? c == '\'' : isQuote(c))
			return j + 1;
		j++;
	}
	return text.length();

A backslash only skips the following character inside single quotes, and the backslash stays in the value. Double-quoted text uses the &quot; token for a quote. An unterminated string extends to the end of the source. Strings may span lines.

Boolean literals

booleanLiteralAt matches exactly <true;> and <false;>. They are copied whole, so their semicolon never ends a statement.

Brackets and newlines

(, [ and { raise the depth. The closers lower it and never take it below zero, so a stray closer is harmless. Newlines inside brackets belong to the statement, which is how multi-line blocks and NBT work. At depth zero, a newline with unfinished text is a syntax error:

if (depth == 0 && c == '\n') {
	if (!current.toString().isBlank())
		throw new SyntaxError(line, OLD_RUN.matcher(current.toString().trim()).matches()
			? "Put more than one statement after run in { }, not ( )" : "Missing ; at the end of the line");
	line++;
	i++;
	continue;
}

OLD_RUN is the pattern (?s).*\brun\s*\(.*\). At the end of the source, a positive depth gives Missing closing bracket and unfinished text gives Missing ; at the end of the line.

Semicolons and tokens

A semicolon at depth zero ends the statement unless it closes a token. endsToken looks at the text since the last &. If that is at most 11 characters and matches &[#A-Za-z0-9\\]+, the semicolon is part of a token. The test is purely on shape and does not consult the token table, so say Tom&Jerry; does not end at its semicolon.

Block endings

After each ordinary character, a } at depth zero ends the statement if isBlock accepts the text. isBlock removes a leading local: or global:, then accepts text that begins with * or matches BLOCK_RUN, the pattern (?s).*\brun\s*\{.*\}. These blocks need no semicolon, and an extra one produces an empty piece that add discards.

Statement is a sealed interface whose records all carry the line they began on.

Dispatch order

statement(line, text) decides the kind of statement in this order:

  1. Text starting with * goes to eventBlock.
  2. A leading local: or global: is removed and the rest is parsed again. The definer has no effect on the statement.
  3. One leading / is removed.
  4. words splits the text. A first word of execute goes to execute.
  5. store followed by new or set goes to store.
  6. store.global goes to storeGlobal.
  7. mark goes to mark.
  8. if or unless must be followed by comp and then goes to execute. Otherwise the error is Minecraft's if needs execute in front: execute if ... (with unless when that was the word), which repeats the whole statement after execute.
  9. Anything else becomes a Command.

Word splitting

words splits on whitespace at bracket depth zero and keeps strings whole, so selectors, NBT and function calls stay single words. topLevelIndex finds the first target text outside brackets and strings, and is used to find the = in store new.

Store grammar

store new <name> {, <name>} = <expression>
store (new|set) font(<name>) as <JSON>
store set <name> ++
store set <name> --
store set <name> as <expression>
store set <name> (= | + | - | * | / | /%) <expression>
store.global set excrd = <x y z>

Names may carry a leading $, which variableName removes, and must match [A-Za-z_][A-Za-z0-9_]*. In the store set forms, the name ends at whitespace or at any of = + - * /, so spaces around those operators are optional. ++ and -- must be the whole remainder. as needs a following space. The other operators are tried in the order /%, =, +, -, *, /, and the text after the operator must be an expression, so += fails with Unexpected =.

For font(, the text between the first ( and ) is the name and everything after as is kept as raw JSON. store new font and store set font produce the same record and differ only in the wording of the syntax error.

Mark grammar

mark add <x y z> [static|mobile]
mark add relative <selector> [<~ ~ ~>]

A trailing static or mobile is removed from the fixed form. The relative form defaults its offset to ~ ~ ~. store.global set excrd = <x y z> builds the same Mark record with a null selector, using the text after the first =.

Execute grammar

execute(line, text) walks the words until it finds run, recording the character offset so the text after run can be taken verbatim. Words that are part of an if comp or unless comp are parsed into Comparison records. All other words are kept as vanilla subcommands.

if ((word.equals("if") || word.equals("unless")) && i + 1 < words.size() && words.get(i + 1).equals("comp")) {
	if (i + 4 >= words.size())
		throw new SyntaxError(line, "if comp needs <value1> <operator> <value2>");
	String operator = words.get(i + 3);
	if (!ComScriptSyntax.COMPARISONS.contains(operator))
		throw new SyntaxError(line, "Unknown comparison " + operator + " (use ==, !=, <, >, <= or >=)");
	comparisons.add(new Comparison(word.equals("unless"), expression(line, words.get(i + 2)), operator, expression(line, words.get(i + 4))));
	for (int k = 1; k <= 4; k++)
		offset = text.indexOf(words.get(i + k), offset) + words.get(i + k).length();
	i += 4;
	continue;
}

Each compared value is exactly one word. A value containing spaces must be wrapped in brackets, such as ($a + 1), because bracket depth keeps it as one word.

After the loop:

  • With no run and no comparisons, the statement becomes the plain Command execute <text>. With comparisons, the error is Expected run after if comp.
  • Empty text after run gives Expected a command after run.
  • Text wrapped in { } is parsed as a statement list.
  • Text wrapped in ( ) gives Put more than one statement after run in { }, not ( ).
  • Anything else is a single statement parsed by statement, so run if comp ... nests.

Event block grammar

eventBlock takes the text between * and the first {, trimmed. It must be empty, all digits (at most 9) or a member of ComScriptSyntax.EVENTS, which is compared exactly and is case-sensitive. The body is parsed with the correct starting line.

Expressions

Expressions are parsed when the script is parsed. ExpressionError is caught in ComScriptParser.expression and rethrown as a SyntaxError with the statement's line.

Tokenizer

tokenize produces a list of strings. At each position it tries:

  1. A boolean literal, <true;> or <false;>.
  2. Whitespace, which is skipped.
  3. @ followed by letters, digits, . and _, plus a balanced [ ] group if one follows.
  4. A string starting with any double quote or '.
  5. A number: a digit, or . followed by a digit, then any run of digits and dots.
  6. A word starting with a letter, _ or $ and continuing with letters, digits, _ and .. A ^ directly before ( is absorbed into a word not starting with $, which is how sin^( is read.
  7. A two-character operator: /%, ==, !=, <=, >=.
  8. A one-character operator from +-*/^(),<>?=.
  9. Any other character is the error Unexpected character 'c'.

The absorbed ^ also applies to a bare variable name, so x^(2) reads as a call and gives Unknown function x^(). $x^(2) and x ^ (2) are powers.

Grammar

The nested Parser class is a recursive-descent parser producing Literal, Variable, Unary, Binary and Call nodes.

additive       := multiplicative { ("+" | "-") multiplicative }
multiplicative := power { ("*" | "/" | "/%" | "mod") power }
power          := unary [ "^" power ]
unary          := "-" unary | primary [ "?" ]

Because power takes its base from unary, -2 ^ 2 evaluates to 4. mod is rewritten to /% while parsing. The ? carries no meaning and is accepted after any value.

Primary values

  • A number containing a dot is parsed by Double.parseDouble, otherwise by Long.parseLong. Failure gives Invalid number X.
  • A string becomes a literal with its quotes removed and substituteTokens applied. $variables are not filled in inside these strings.
  • Bare true or false gives Write booleans as <true;> or Write booleans as <false;>.
  • A token starting with @ becomes a Selector literal.
  • A letter-initial token before ( must satisfy ComScriptSyntax.isFunction, or the error is Unknown function x(). The name is lowercased, so function names are case-insensitive. Each argument's tokens are also joined into a raw string, used by bin().
  • A word with no bracket is a Variable. The $ is therefore optional in values.

Numeric rules

binary evaluates both sides first. Comparison operators go to compare. + with a String on either side joins the format of both values. All other operators need two numbers. When both are Long the arithmetic is Java 64-bit long arithmetic. If either is a Double, both are widened.

case "/":
	// Remainderless division; dividing by 0 gives 0
	if (y == 0)
		return 0L;
	return integers ? (Object) Math.floorDiv((Long) a, (Long) b) : x / y;
case "/%":
	if (y == 0)
		return 0L;
	return integers ? (Object) Math.floorMod((Long) a, (Long) b) : x - Math.floor(x / y) * y;
case "^":
	double result = Math.pow(x, y);
	return integers && y >= 0 && Math.abs(result) < 9.0E18 ? (Object) (long) result : result;

  • Integer division rounds toward negative infinity, so -7 / 2 is -4.
  • The integer remainder takes the divisor's sign. The float remainder is x - floor(x / y) * y.
  • Division or remainder by zero returns the integer 0 for floats as well.
  • ^ gives an integer only for two integers with a non-negative exponent and a result below 9.0E18 in size.
  • Unary minus accepts only numbers.

Comparison rules

==, = and != compare two numbers by their double value and everything else with equals. Values of different kinds are simply unequal. The ordering operators accept two numbers (Double.compare) or two strings (compareTo). Any other pairing is a type error.

Formatting

format decides how a value appears in commands and in string joins.

public static String format(Object value) {
	if (value instanceof Double d) {
		if (Double.isNaN(d) || Double.isInfinite(d))
			return Double.toString(d);
		// Rounded to 10 decimal places so sin(30) shows as 0.5
		java.math.BigDecimal rounded = java.math.BigDecimal.valueOf(d).setScale(10, java.math.RoundingMode.HALF_UP).stripTrailingZeros();
		return rounded.scale() <= 0 ? rounded.toBigInteger().toString() : rounded.toPlainString();
	}
	return String.valueOf(value);
}

private static String toBinary(Object value, String raw) {
	if (raw.matches("[01]+"))
		return raw;
	if (value instanceof Long l)
		return Long.toBinaryString(l);
	if (value instanceof Boolean b)
		return b ? "1" : "0";

Filling commands

fill is applied to command text, mark selectors and positions, execute subcommands and style JSON. It matches \$([A-Za-z_][A-Za-z0-9_]*) anywhere in the text, including inside quotes, and reads only the variable map.

private String fill(String text) {
	Matcher matcher = VARIABLE.matcher(text);
	StringBuilder out = new StringBuilder();
	while (matcher.find()) {
		Object value = variables.get(matcher.group(1));
		if (value == null)
			throw ScriptError.undefined("$" + matcher.group(1));
		matcher.appendReplacement(out, Matcher.quoteReplacement(ComScriptExpression.format(value)));
	}
	matcher.appendTail(out);
	return ComScriptSyntax.substituteTokens(out.toString());
}

Token substitution

ComScriptSyntax.substituteTokens finds each & with a ; at most 12 characters later and looks up the text between them, inclusive. It tries the table first, then the form &#\d+;, which becomes that code point. Unrecognised text is left alone. The runner

ComScriptRunner implements ComScriptExpression.Environment, giving expressions access to variables, the current command source, the Scripter's level and its random source.

Statement budget

STATEMENT_LIMIT is 10000, so that a script can't freeze the server. run sets the budget each time it is entered: once for the main run, and once for each firing of a timer or event. Every statement costs one, including the statements inside blocks, once per context they run in. Exceeding the budget throws the private StopRun, which stops only that run, tick or event. Listeners stay registered.

private void runBody(List<Statement> statements, CommandSourceStack source) {
	for (Statement statement : statements) {
		if (--budget < 0)
			throw new StopRun();
		scripter.currentLine = statement.line();
		try {
			source = execute(statement, source);
		} catch (ScriptError e) {
			scripter.log(ScripterBlockEntity.ERROR, statement.line(), e.getMessage());
		} catch (StopRun e) {
			throw e;
		} catch (RuntimeException e) {
			scripter.log(ScripterBlockEntity.ERROR, statement.line(), "Error: " + e);
		}
	}
}

A failed statement is logged and the next one runs. currentLine is what gives command output its line number.

Source propagation

execute returns the source that later statements use. Only Mark returns a different one. The change is local to the statement list being run, because source is a local variable of runBody. A block starts from the source it was given and its own mark lines do not leak out. The field current is set at the start of each statement and is what fetchers use to resolve selectors.

Mark execution

The target becomes positioned <position>, prefixed with at <selector> in the relative form. contexts runs that through vanilla's execute. Only the first resulting position is used, and only the position changes. No contexts gives Error: No mandatory execution marker found: nothing matched <selector>, where a fixed position with invalid coordinates prints null as the selector, and the marker stays where it was.

Execute and if comp evaluation

case ComScriptParser.Execute execute -> {
	for (ComScriptParser.Comparison comparison : execute.comparisons()) {
		Object left = ComScriptExpression.evaluate(comparison.left(), this);
		Object right = ComScriptExpression.evaluate(comparison.right(), this);
		if ((Boolean) ComScriptExpression.binary(comparison.operator(), left, right) == comparison.negate())
			return source;
	}
	if (execute.subcommands().isEmpty())
		runBody(execute.body(), source);
	else
		for (CommandSourceStack context : contexts(fill(execute.subcommands()), source))
			runBody(execute.body(), context);

Pseudocode not written yet.

The order matters:

  1. All comparisons are evaluated first, once, in written order, against the source the statement started with, wherever they appear among the subcommands.
  2. The first comparison that fails ends the statement.
  3. With no vanilla subcommands, the body runs once from the same source.
  4. Otherwise, fill is applied to the subcommands, vanilla's execute collects the contexts, and the body runs once per context.

A comparison that must see each entity's @s therefore goes inside the body:

execute as @a at @s run {
    if comp getHealth(@s) < 5 run say low health;
}

The callback command

Vanilla's parser runs the subcommands, and a hidden command records where they reach. ComScript.CALLBACK_COMMAND is comscript_callback, which takes an integer id of at least 0 and requires gamemaster permission level.

private List<CommandSourceStack> contexts(String subcommands, CommandSourceStack source) {
	int id = nextCallback++;
	List<CommandSourceStack> found = new ArrayList<>();
	CALLBACKS.put(id, found);
	try {
		runCommand("execute " + subcommands + " run " + ComScript.CALLBACK_COMMAND + " " + id, source);
	} finally {
		CALLBACKS.remove(id);
	}
	return found;
}

Commands are sent with performPrefixedCommand, and a failing subcommand reports through the terminal like any command.

Timers

An EventBlock statement calls ScripterBlockEntity.listen, which stores a Listener and continues with the next statement. Timers are non-blocking and repeat until the listeners are cleared.

private record Listener(String event, List<ComScriptParser.Statement> body, CommandSourceStack source, ComScriptRunner runner, long started) {
	boolean isTimer() {
		return event.isEmpty() || Character.isDigit(event.charAt(0));
	}

	int interval() {
		return event.isEmpty() ? 1 : Integer.parseInt(event) + 1;
	}

	String describe() {
		return !isTimer() ? event : interval() == 1 ? "every tick" : "every " + interval() + " ticks";
	}
}

Because registration is an ordinary statement, it obeys the flow around it. Inside if comp it registers conditionally. Inside execute as @a at @s run { } it registers once per context. Inside a timer or event body, it registers another listener each time that body runs, with no limit on the number of listeners. Listeners added during a tick are first examined on the next one, because the loop uses a copy.

public static void fire(Level level, String event, Vec3 position, @Nullable Entity entity, Map<String, Object> details) {
	for (ScripterBlockEntity scripter : List.copyOf(LISTENING))
		if (scripter.level == level && !scripter.isRemoved())
			for (Listener listener : List.copyOf(scripter.listeners))
				if (listener.event().equals(event)) {

					if (entity != null)
						source = source.withEntity(entity);
					listener.runner().variables.putAll(details);
					listener.runner().run(listener.body(), source);
					scripter.currentLine = -1;
				}
}

Native fetchers

ComScriptFetchers.NAMES lists 53 lowercase names, and call is a switch over them. Names are case-insensitive. The level is always env.source().getLevel(), the level of the statement being run. Selectors resolve against that same source. A fetcher can be used in any value but is not evaluated in raw command text.

Argument resolution

static List<? extends Entity> entities(Node arg, Environment env) {
	String text;
	if (arg instanceof Variable variable && env.variable(variable.name()) == null)
		text = variable.name();
	else {
		Object value = ComScriptExpression.evaluate(arg, env);
		text = value instanceof Selector selector ? selector.text() : ComScriptExpression.format(value);
	}
	try {
		return EntityArgument.entities().parse(new StringReader(text)).findEntities(env.source());
	} catch (CommandSyntaxException e) {
		throw new ScriptError("Error: " + e.getMessage());
	}
}

An entity argument is a selector, a player name (quoted or bare), or a variable holding either. Single-entity fetchers use the first match and fail with Error: No entity matched <argument>. Position arguments must be numbers and are converted with BlockPos.containing.

The fetchers marked "loaded" below use loadedPosition, which fails with Error: the chunk at x, y, z isn't loaded.
