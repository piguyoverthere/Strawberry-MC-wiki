Vanilla Command Integration

ComScript also supports native vanilla commands to be executed once the required components are specified. Components are each specifier (such as .permissionLevel or .executeAs) shown in the example below.

Vanilla command execution example:

store new time = "day"
server.executeComponents { // client.executeCompotnents can be used for client-side commands
    .permissionLevel(4);
    .suppressOutput(<true;>);
}
server.getCommandStack().execute("time set ", $time)

Note

This script sets the time to the $time variable, which in this case is "day", at permission level 4 (operator status) and output suppressed.

Components

.executeAs(<entity>);

.executeAs executes the command as the entity specified, which both sets the execution location to the location of the specified entity and also defines @s as the specified entity. This component also overrides any execution marker previously specified. Note .executeAs does not support filters or ranges which you will learn about later.

When no .executeAs is provided, it executes as the Scripter and errors for any command that requires a entity, or it inherits the mobile execution marker (or entity execution marker, which is a entity to execute as in the header file.) (you will learn this later) in the header file.

.executeAt(<x>, <y>, <z>);

.executeAt executes at the coordinates specified, which only sets the execution location/marker but not the execution entity, where it differs from .executeAs.

.permissionLevel(<int>);

.permissionLevel specifies the permission level that the command should execute as:

  • 1: Guest
  • 2: Manager
  • 3: Moderator
  • 4: Operator
  • See Usage: Purpose: Permission levels for more information

Different permission levels can restrict certain commands or alter the outcome.

.suppressOutput(<boolean>);

.suppressOutput when true prevents the action from being logged into public chat.

Since components are not required to execute a function, the default value is true unless otherwise stated in the script.
