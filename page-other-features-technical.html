Other Features [technical]

This page collects the code behind the sections of Other Features: Overworld terrain generation, villager trades, soil, the waypoint location helper, the Smite Vial on Chiseled Cauldrons, and the Shocking enchantment.

Terrain generation

See also the main page, Terrain Generation. Overworld biomes are added by extending the vanilla multi-noise biome source, not by replacing it. Three pieces work together: StrawberrymcModBiomes, generated by MCreator from the biome elements; the mixins BiomeSourcePresetMixin and NoiseGeneratorSettingsMixin, also generated; and the hand-written SurfaceBiomeDepthMixin.

Biome source preset

BiomeSourcePresetMixin targets MultiNoiseBiomeSourceParameterList.Preset and injects at the end of its constructor. For the identifiers minecraft:overworld and minecraft:nether, it replaces the preset's provider field with a provider that runs the original one first and passes the result through the mod.

Climate.ParameterList<T> originalList = existingProvider.apply(lookup);
return StrawberrymcModBiomes.adaptPresetParameterList(idArg, originalList, lookup);

adaptPresetParameterList returns the list unchanged until FMLCommonSetupEvent has set BOOTSTRAP_VALIDATION_PASSED. After that, it only changes the Overworld list, by calling modifyOverworldParameterPoints. The Nether preset is wrapped but keeps its original list.

Climate parameters

modifyOverworldParameterPoints copies the vanilla list and appends one Climate.ParameterPoint per entry below, each with an offset of 0. The surface biomes are added twice, once for the depth point 0.0 and once for 1.0, which are the two depth points vanilla uses for surface biomes.

Claiming the climate box

Vanilla already covers every climate value, so an appended biome only ties with the vanilla biome at the same point. SurfaceBiomeDepthMixin injects at the return of modifyOverworldParameterPoints and, for each biome in its SURFACE_BIOMES list (alpine_meadow and ocean_abyss), cuts that biome's climate boxes out of every other surface biome. Inside those ranges the listed biome is the only candidate.

A point is a surface point when its depth is a single value equal to the quantized 0.0 or 1.0. Cave biomes use other depths, so they are skipped. subtract splits a box against the cut one axis at a time, emitting the slices above and below the cut and narrowing the remaining box before the next axis. If any axis does not overlap, the box is returned whole.

for (int i = 0; i < from.length; i++) {
	if (rest[i].min() < cut[i].min()) {
		Climate.Parameter[] below = rest.clone();
		below[i] = new Climate.Parameter(rest[i].min(), cut[i].min());
		pieces.add(below);
	}
	if (rest[i].max() > cut[i].max()) {
		Climate.Parameter[] above = rest.clone();
		above[i] = new Climate.Parameter(cut[i].max(), rest[i].max());
		pieces.add(above);
	}
	rest[i] = new Climate.Parameter(Math.max(rest[i].min(), cut[i].min()), Math.min(rest[i].max(), cut[i].max()));
}

The biome-specific consequences are covered in Alpine Meadowlands [technical] and Ocean Abyss [technical]. The latter also explains the mod's overrides of the vanilla density functions overworld/offset.json and overworld/factor.json.

Surface rules

NoiseGeneratorSettingsMixin wraps NoiseGeneratorSettings.surfaceRule with a @WrapMethod and stores a Holder<DimensionType> in a @Unique field. On ServerAboutToStartEvent, StrawberrymcModBiomes walks the LEVEL_STEM registry and sets that field on the settings of each Overworld or Nether stem using a NoiseBasedChunkGenerator. adaptSurfaceRule only acts for the Overworld type.

injectOverworldSurfaceRules builds a sequence with the mod's rules first, then every rule of the vanilla sequence, so a custom biome's rule is tested before vanilla's. Two rule builders exist.

SetTemperatureBiomeModifier is a custom modifier registered with the codec name strawberrymc:set_temperature. Its comment explains its purpose: a biome below temperature 0.15 gets snow, so this keeps Alpine Meadow snow-free without editing the biome JSON that MCreator generates.

@Override
public void modify(Holder<Biome> biome, Phase phase, ModifiableBiomeInfo.BiomeInfo.Builder builder) {
	if (phase == Phase.MODIFY && this.biomes.contains(biome))
		builder.getClimateSettings().setTemperature(this.temperature);
}

Vanilla biome tags in data/minecraft/tags/worldgen/biome are extended with "replace": false. is_overworld, is_ocean and is_deep_ocean gain ocean_abyss. The has_structure tags place buried_treasure, pillager_outpost, ruined_portal_swamp and shipwreck_beached in clover_glades, jungle_temple in montane_jungle, and mineshaft and stronghold in crystal_hollows.

A trade is a JSON file in data/strawberrymc/villager_trade/<profession>/<level>, and it joins the vanilla pool by name through the tag data/minecraft/tags/villager_trade/<profession>/level_<level>.json.

Waypoint location helper

See also the main page, Waypoints. CalculateWaypointLocationProcedure [raw] is a hand-written class in the procedures package with no matching MCreator element. It has one public static method, and no other class in the mod references it.

public record PredictionResult(boolean isPresentInChunk, BlockPos position) {}

public static PredictionResult predictRareVegetalLocation(long worldSeed, int chunkX, int chunkZ, int rarityChance)

The method predicts where a feature with a rarity filter would land in a chunk, without generating the chunk. In order:

  1. It creates a WorldgenRandom over XoroshiroRandomSource(0L) and calls setDecorationSeed(worldSeed, chunkX << 4, chunkZ << 4).
  2. It takes one nextLong() from that generator as a salt and builds a second WorldgenRandom from it.
  3. If the second generator's nextInt(rarityChance) is not 0, it returns PredictionResult(false, BlockPos.ZERO).
  4. Otherwise, it takes offsetX and offsetZ as nextInt(16) from the first generator and returns the chunk's block coordinates plus those offsets.

The Y coordinate of a positive result is always the constant 64, labeled in the source as a baseline for ungenerated terrain.

Chiseled Cauldron and the Smite Vial

See also the main pages, Chiseled Cauldrons and Spells For Chiseled Cauldrons.

Chiseled Cauldron block

ChiseledCauldronBlock is registered as strawberrymc:chiseled_cauldron from the element ChiseledCauldron.mod.json. Its item has stacksTo(1) and Rarity.RARE. The block's properties are unbreakable hardness and blast resistance (strength(-1, 3600000)), no occlusion, PushReaction.BLOCK, always-on emissive rendering, and redstone conduction disabled. It implements SimpleWaterloggedBlock with the usual WATERLOGGED property.

Its collision shape is a 5-pixel base plus four 2-pixel walls reaching the full block height, with an empty visual shape. getBlockPathType returns PathType.BLOCKED, so mobs do not path through it. The item appears in the Functional Blocks tab, the Operator Blocks tab and the mod's Developer tab.

private static final VoxelShape SHAPE = Shapes.or(box(0, 0, 0, 16, 5, 16), box(0, 5, 0, 16, 16, 2), box(0, 5, 14, 16, 16, 16), box(0, 5, 2, 2, 16, 14), box(14, 5, 2, 16, 16, 14));

animateTick calls AmbientParticleEnchantProcedure [raw] with the block position. Block.animateTick is only invoked from ClientLevel, and the procedure spawns its ParticleTypes.ENCHANT particles only when the world is a ServerLevel, so the call emits nothing.

Smite Vial

SmiteVialItem has Rarity.UNCOMMON and appears in the Ingredients and Combat tabs. Its element's onRightClickedOnBlock trigger is the procedure SmiteHandler, which the generated item class calls from useOn with the clicked block's coordinates. The item always returns InteractionResult.SUCCESS.

SmiteHandlerProcedure [raw] does nothing unless the clicked block is a Chiseled Cauldron. Otherwise, in order:

  1. It plays item.bucket.empty at the cauldron, in the Master sound category, at volume 1 and pitch 1.
  2. It collects all entities in a box centered on the block's integer corner and inflated by 5, sorted nearest first, and skips the caster.
  3. For each remaining entity, it spawns a LightningBolt with EntitySpawnReason.TRIGGERED at the bottom center of the entity's block, on the server only, and plays entity.arrow.hit_player at the entity.
  4. It sends 36 ParticleTypes.ANGRY_VILLAGER particles one block above the cauldron from the server, with spread (cos(Angle), 0, sin(Angle)) and speed 1, adding 10 to Angle after each one.
  5. It shrinks the held stack by one unless the caster is in Creative mode.
for (int _i1 = 0; _i1 < 36; _i1++) {
	if (world instanceof ServerLevel _level)
		_level.sendParticles(ParticleTypes.ANGRY_VILLAGER, x, (y + 1), z, 1, Math.cos(Angle), 0, Math.sin(Angle), 1);
	Angle = Angle + 10;
}

EntityShock

EntityShockProcedure [raw] subscribes to LivingDamageEvent.Pre. The check runs on the entity being damaged, reading the item that entity is using at that moment. When that use item carries the enchantment, the procedure sends two each of ANGRY_VILLAGER, ENCHANTED_HIT and GUST particles at the entity (spread 1, speed 1) and applies extra damage.

Extra damage comes from hurtServer calls using the strawberrymc:shocking damage type. The damage type's JSON has exhaustion 0.2, scaling always and effects poking, and its language keys supply the death messages. Each check below is independent, so more than one can apply.

The procedure then rolls Mth.nextInt(RandomSource.create(), 1, 8). On a 1, it picks a slot index from 100 to 103 with another roll, spawns that slot's stack as an ItemEntity with a pickup delay of 5, clears the slot through the entity's Capabilities.Item.ENTITY resource handler inside a transaction, and plays item.shield.break in the Neutral category.

The damage type is defined by the separate Shocking.mod.json element, so the element named Shocking is the damage type and the element named Electricution is the enchantment.
