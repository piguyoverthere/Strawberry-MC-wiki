Ocean Monument [technical]

Overview and source map

The Ocean Monument is built from a set of mixins on vanilla's monument classes, one static builder class, and three event-driven gameplay classes. StrawberrymcMod calls MonumentIntro.init, MonumentPuzzlesPack.init, PrismaticSensors.init, MonumentArena.init and MonumentQuest.init on the mod event bus. Each one registers its own deferred registers, payloads and NeoForge event listeners.

The arena on the roof is documented on Prismatic Vault. The puzzle jigsaw datapack is documented on P2 Piston Puzzle. The roof vent's blocks are documented on Ancient Prismarine.

Its spawn_overrides give the monster category one entry, minecraft:guardian with weight 1, min count 2 and max count 4, over the full bounding box. Sitting on the sea floor

Vanilla builds monuments with their base at y=39. OceanMonumentFloorMixin injects at TAIL of OceanMonumentStructure.generatePieces. The building's constructor has already been widened by the shell mixin, so the builder's box is the full 116x116 footprint. The mixin samples a 5x5 grid across that box with Heightmap.Types.OCEAN_FLOOR_WG, subtracts 1 from each height to get the floor block, and keeps the lowest value.

int dy = Math.max(lowestFloor, LOWEST_BASE_Y) - box.minY();
// Only ever move down; vanilla height is fine wherever the floor is higher
if (dy < 0)
	builder.offsetPiecesVertically(dy);

LOWEST_BASE_Y is -58. Bedrock reaches y=-60, so this leaves some deepslate under the monument. Monument pieces are regenerated at y=39 whenever a chunk is loaded from disk, so a second injection at RETURN of regeneratePiecesAfterLoad moves every rebuilt piece by the difference between the saved and rebuilt minY.

Basin

MonumentBasinMixin targets Structure and checks this instanceof OceanMonumentStructure. A structure may only place blocks in chunks its bounding box covers, so the injection at RETURN of adjustBoundingBox widens the box by 56 on the X and Z sides. The injection at HEAD of afterPlace does the digging, column by column across the chunk.

ConstantValueMeaning
FLAT_RING8Blocks of flat floor around the monument at base height.
BASIN_RADIUS56Outer limit of the dig, far enough for the slope to climb from y=-58 to the usual abyss floor.
MAX_CAVE_FLOOD16The cave flood loop runs while y > floorY - 16, so up to 15 blocks.
 
int dx = Math.max(0, Math.max(monument.minX() - x, x - monument.maxX()));
int dz = Math.max(0, Math.max(monument.minZ() - z, z - monument.maxZ()));
// Inside the footprint the monument already fills everything with water
if (dx == 0 && dz == 0)
	continue;
double distance = Math.sqrt(dx * dx + dz * dz);
if (distance > BASIN_RADIUS)
	continue;

int floorY = monument.minY() + (int) Math.max(0, distance - FLAT_RING);

The floor therefore rises one block per block of distance after the flat ring. Per column, in order:

  1. Every non-water block from floorY up to sea level becomes water, and the column is marked as dug.
  2. Air directly below floorY becomes water, stopping at the first non-air block.
  3. If the column was dug, and the block at floorY - 1 is in BlockTags.BASE_STONE_OVERWORLD with a solid block beneath it, that block becomes minecraft:gravel.

MonumentBuildingShellMixin injects at TAIL of the MonumentBuilding constructor and assigns MonumentShell.scaledBox(box), which grows the box by 29 on each horizontal side around the same center. It injects at HEAD of postProcess, calls MonumentShell.place and cancels vanilla. Both injections do nothing while MonumentShell.isRecording() is true.

Recording vanilla's shell

Instead of reimplementing the monument's walls, MonumentShell runs vanilla's own code once per orientation. record(Direction) sets a ThreadLocal recording flag, builds a MonumentBuilding at (0, 0), and clears its child pieces, which removes every room and leaves the outer shell. It then calls postProcess with a fake world.

OceanMonumentPieces.MonumentBuilding building = new OceanMonumentPieces.MonumentBuilding(RandomSource.create(0), 0, 0, orientation);
// Hollow: without its rooms, only the outer shell is built
((MonumentBuildingAccessor) building).strawberrymc$getChildPieces().clear();
BoundingBox box = building.getBoundingBox();
building.postProcess(recorder(recorded, box), null, null, RandomSource.create(0), new BoundingBox(-64, -64, -64, 128, 128, 128),
	new ChunkPos(0, 0), BlockPos.ZERO);

The fake world is a java.lang.reflect.Proxy of WorldGenLevel. It handles these methods:

  • setBlock writes the state into a flat array, indexed by vanilla-scale local position.
  • getBlockState and getFluidState read that array, returning air for anything unrecorded.
  • getSeaLevel returns 69 (39 + 30), so water fills up to MAX_LY.
  • getMinY returns 36, so support pillars stop one block under the floor.
  • scheduleTick is a no-op; isClientSide returns false; hashCode, equals and toString are answered directly.
  • Default interface methods are invoked normally, and anything else throws UnsupportedOperationException.

Air and water are dropped from the result, leaving only solids. Results are cached in a ConcurrentHashMap<Direction, Recording>.

The roof height comes from the recording as well. Scanning down from MAX_LY, roofTop is the first layer in which at least 50 of the central 10x10 columns are solid. Sparse decoration above the slab does not reach that count, so the gazebo sits on the real roof.

Placing the shell

MonumentShell.place loops over the columns where the box and chunk overlap. Each world block maps to vanilla-scale coordinates by integer division, so every recorded block becomes a 2x2x2 cube.

int lx = (x - box.minX()) / SCALE, lz = (z - box.minZ()) / SCALE;
// Vanilla's support pillars reach down to the sea floor
BlockState pillar = recording.get(lx, -1, lz);
if (pillar != null) {
	pos.set(x, box.minY() - 1, z);
	while (pos.getY() > level.getMinY() + 1 && isReplaceable(level.getBlockState(pos))) {
		level.setBlock(pos, pillar, 2);
		pos.move(Direction.DOWN);
	}
}
for (int y = box.minY(); y < top; y++) {
	BlockState state = recording.get(lx, (y - box.minY()) / SCALE, lz);
	if (state == null)
		state = y < box.minY() + SCALE ? FLOOR : y < seaLevel ? WATER : Blocks.AIR.defaultBlockState();

top is max(seaLevel, minY + 46). FLOOR is minecraft:prismarine_bricks, so the hollow interior has a floor two blocks thick and water above it. isReplaceable accepts air, liquids, seagrass, tall seagrass, kelp and kelp plant. After the shell, buildGazebo, buildArena and buildSensors run in that order.

The Layout record

MonumentShell.Layout(box, orientation, floorY) holds every position used by the server and sent to the client. floorY, the top of the roof and the height of the gazebo floor, equals box.minY() + 2 * (roofTop + 1). Local coordinates put the entrance at z=0 and are converted by world(x, y, z).

Vent eruption

Server side

PrismaticSensors.onBreak listens to BreakBlockEvent and calls checkVent when Ancient Prismarine is broken. checkVent requires three things: the position is one of the 9 cap blocks, the vent is not already in the ERUPTING set, and the dome's center block (floor + 7) is still Cracked Prismarine. The last check is what makes the eruption happen only once per monument.

BlockPos vent = layout.ventCenter();
ERUPTING.add(vent);
for (ServerPlayer player : level.players())
	if (player.blockPosition().closerThan(vent, CUTSCENE_RANGE)) {
		PacketDistributor.sendToPlayer(player, new PlayVentCutscene(vent, layout.lumpCenter()));
		MonumentIntro.protect(player, VENT_CUTSCENE_TICKS);
	}
level.playSound(null, vent, SoundEvents.BUBBLE_COLUMN_UPWARDS_AMBIENT, SoundSource.BLOCKS, 2.0F, 0.6F);
for (int t = 0; t <= JET_HIT - JET_START + 20; t += 2) {
	int tick = t;
	io.github.strawberrymc.StrawberrymcMod.queueServerWork(JET_START + t, () -> jet(level, layout, tick));
}
io.github.strawberrymc.StrawberrymcMod.queueServerWork(JET_HIT, () -> shatter(level, layout));
io.github.strawberrymc.StrawberrymcMod.queueServerWork(VENT_CUTSCENE_TICKS, () -> ERUPTING.remove(vent));

CUTSCENE_RANGE is 48 blocks. In jet, the jet's height is min(1, tick / 40) * (domeTip.y - vent.y), 5 blocks at full height. Every half block up the jet it sends minecraft:bubble_column_up (6 particles, spread 0.6/0.2/0.6, speed 0.1) and minecraft:cloud (2 particles, spread 0.4/0.2/0.4, speed 0.02). The top gets 10 minecraft:bubble_pop (spread 0.7/0.3/0.7, speed 0.05).

Client side

VentCutscene.start ignores the packet if another cutscene is playing. The shot is computed once:

  • The target is halfway between the top of the vent and the dome's center block.
  • The horizontal direction from the vent to the player is snapped to 22.5 + 45n degrees, which lands between two pillars.
  • The desired position is 15 blocks from the target along that direction and 0.5 up.
  • A clip ray runs from 1.5 above the vent. On a hit, the camera stops 0.8 short of the block, but never closer than 2.5 from the anchor.
  • If the line from the player's eyes to the shot is blocked, dip is set. The pan becomes a cut at its midpoint, with black at ticks 11 and 109, ramping over 8 ticks each side.

While active, it cancels all RenderGuiLayerEvent.Pre layers, the hand and the water screen overlay, and draws black bars 9% of the screen height, sliding over 15 ticks. Fog is lerped to near 24 and far 64 by min(ease(t / 22), ease((120 - t) / 22)). Easing throughout is smoothstep, t * t * (3 - 2 * t).

Entrance cutscene

Trigger

MonumentIntro.onPlayerTick listens to PlayerTickEvent.Post and returns unless the player is a ServerPlayer, tickCount % 10 == 0 (every 0.5 seconds), not a spectator, and has not seen the cutscene. Being seen is the attachment strawberrymc:seen_monument_intro, a boolean saved under the field seen and copied on death.

When the player is inside the building's box, the method runs these steps in order:

  1. Takes the first structure piece and its box. The entrance direction is the opposite of the piece's orientation.
  2. Picks the sensor nearest the player, because its chunk is sure to be loaded on their client.
  3. Sets the seen attachment to true.
  4. Stores the protection expiry as game time plus 425.
  5. Clears the target of every Mob within 64 blocks that is targeting the player.
  6. Sends PlayCutscene(min, max, entrance, vent, sensor).

Protection

PROTECTED_UNTIL maps player UUID to a game time and is shared by all three monument cutscenes. protect(player, ticks) merges with Math::max. Two listeners read it:

  • LivingIncomingDamageEvent is cancelled unless the source is in DamageTypeTags.BYPASSES_INVULNERABILITY, so /kill and the void still work.
  • LivingChangeTargetEvent is cancelled when the new target is a protected player, which stops guardians and every other mob from acquiring the player again.

The player remains the camera entity. The game keeps running throughout, which keeps kelp, seagrass and mobs animated on screen.

How the camera works

MonumentCutscene.start runs from the packet handler. It computes the center at floor level, the half width (58) and the direction towards the player. That direction picks which corner to film, because the client only has chunks loaded near the player. It adds the night vision effect if the player has none: duration 825 ticks, amplifier 0, ambient, hidden. It then plays the chime through SimpleSoundInstance.forUI(CHIME, 1.0F, 1.0F).

Each frame, framing(shot, progress) returns a Framing(anchor, desired, target). The anchor is a point known to be open. The camera sits on the line from the anchor to the desired position, as far along as a clip ray allows.

// The line of sight shrinks instantly when blocked and grows back smoothly
double free = freeDistance(framing.anchor(), framing.desired());
double frameTicks = Math.max(0, time - lastFrameTime);
lastFrameTime = time;
clipDistance = free < clipDistance ? free : clipDistance + (free - clipDistance) * Math.min(1, CLIP_RECOVERY * frameTicks);
Shot view = lookingAt(clipFrom(framing.anchor(), framing.desired(), clipDistance), framing.target());

freeDistance uses ClipContext.Block.VISUAL and Fluid.NONE, with CLIP_MARGIN 1.0 and MIN_DISTANCE 3.0. CLIP_RECOVERY is 0.12 of the remaining distance per tick. clipDistance resets at each new shot.

CutsceneCameraMixin injects at TAIL of Camera.alignWithEntity and applies the shot, with the arena cutscene taking priority, then the vent cutscene, then the entrance cutscene. CutsceneNightVisionMixin overrides GameRenderer.getNightVisionScale with the cutscene's fade strength, avoiding vanilla's flicker as the effect runs out.

The chime strawberrymc:monument_chime (master category, streamed) lives in the built-in client resource pack monument_cutscene, registered always-on at the top of the pack list by MonumentIntro.addPack and titled "Strawberry MC monument cutscene". Keeping it there stops MCreator's generated sounds.json from overwriting it. The same pack carries the sensor_glyph and rune_funnel particle definitions.

onPlayerTick runs every 10 ticks for non-spectators who are not in a cutscene, so the first objective appears after the entrance cutscene.

State state = player.getData(STATE);
// Wandering too far from the objective drops the quest and its ping; it starts over at the next monument entered
if (state.stage() != Stage.NONE && player.position().distanceToSqr(objectivePos(state)) > ABORT_DISTANCE * ABORT_DISTANCE) {
	setStage(player, Stage.NONE, null);
	return;
}
if (state.stage() == Stage.KEY)
	return;
MonumentShell.Layout layout = PrismaticSensors.monumentAt(player.level(), player.blockPosition());
if (layout == null)
	return;
if (state.stage() == Stage.NONE)
	setStage(player, Stage.ARENA, layout);
else if (layout.onArena(player.position()) && READING.add(player.getUUID()))
	reachArena(player, layout);

ABORT_DISTANCE is 400 blocks. Layout.onArena is true within radius 14 of the vault's center and from the vault's y to 6 above it.

reachArena sends the notice "You cannot reach the Monument Key right now." followed by "The vault needs a key." on a second line. While the player's UUID is in READING, sync sends no objective and no objective ping. After NOTICE_TICKS (110 ticks, 5.5 seconds), if the player is still at ARENA, the stage becomes KEY.

Pings

A ping is Ping(id, pos, color, size, blink, label). drawPing projects the world position onto the HUD by hand, which is why pings show through blocks.

double depth = offset.x * forward.x() + offset.y * forward.y() + offset.z * forward.z();
double right = -(offset.x * left.x() + offset.y * left.y() + offset.z * left.z());
double upward = offset.x * up.x() + offset.y * up.y() + offset.z * up.z();
int width = graphics.guiWidth(), height = graphics.guiHeight();
double focal = (height / 2.0) / Math.tan(Math.toRadians(camera.getFov()) / 2);
  • Screen position is width / 2 + right / depth * focal and height / 2 - upward / depth * focal.
  • With depth 0.05 or less, the ping is behind the camera and pushed towards the matching edge.
  • Anything within 22 pixels of the edge, or behind the camera, is clamped along its direction from the screen center to that margin.
  • The shape is one color: a rotated square ring of half-size 7 * size * 1.4 and thickness 1.5, around a solid diamond of half-size 7 * size * 0.6.
  • When blink is true, the ping is hidden while time % 1.2 > 0.85: on for 0.85 seconds and off for 0.35.
  • The text under it is label Nm in the same color. When clamped near the bottom edge, the text moves above the ping.

The objective ping has id objective, color #00E5FF, size 1 and blink on.
